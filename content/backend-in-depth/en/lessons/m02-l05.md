# Algorithm design techniques

## Recursion
<!-- bullets: 2.5.a -->

A recursive method solves a problem by handing a simpler instance of the same problem to itself. It has to reach a case it can answer directly, or it never stops.

A recursive method needs an elementary base case, because there must be no infinite sequence of reductions to simpler and simpler instances (`erickson-recursion#p3`).

Without a base case, the recursive algorithm will loop forever (`erickson-recursion#p3`).

The most common way to satisfy this condition is to reduce to one or more smaller instances of the same problem (`erickson-recursion#p3`).

The Recursion Fairy is the Induction Hypothesis under a less formal name (`erickson-recursion#p3`).

Peasant multiplication returns 0 when x is 0, and otherwise multiplies the integer half of x by y + y and adds y to the product when x is odd (`erickson-recursion#p3`).

The recursive call of peasant multiplication is on a simpler problem because x' < x, and repeatedly decreasing a positive integer eventually leads to 0 (`erickson-recursion#p3`).

The snippet counts the calls of a recursive peasant multiplication.

```java snippet=m02-l05/PeasantMultiplication.java
public class PeasantMultiplication {
    static int calls;

    static int multiply(int x, int y) {
        calls++;
        if (x == 0) {
            return 0;
        }
        int product = multiply(x / 2, y + y);
        return x % 2 == 1 ? product + y : product;
    }

    public static void main(String[] args) {
        System.out.println("13 x 25 = " + multiply(13, 25) + " in " + calls + " calls");
        calls = 0;
        System.out.println("0 x 25 = " + multiply(0, 25) + " in " + calls + " call");
    }
}
```

It prints `13 x 25 = 325 in 5 calls`, and `0 x 25 = 0 in 1 call` when x is already 0, the base case.

## Backtracking: subsets, permutations and pruning
<!-- bullets: 2.5.a -->

Backtracking builds an answer one decision at a time and tries every option for each decision. Each recursive call makes one decision that agrees with the earlier ones, and it needs a summary of those earlier decisions.

Backtracking algorithms are commonly used to make a sequence of decisions, with the goal of building a recursively defined structure satisfying certain constraints (`erickson-backtracking#p9`).

In each recursive call to a backtracking algorithm, exactly one decision is made, and the choice must be consistent with all previous decisions (`erickson-backtracking#p9`).

For each row of the n queens problem, the algorithm decides where to place the queen (`erickson-backtracking#p9`).

In the subset sum problem, the algorithm decides for each input element whether to include it in the output sequence or not (`erickson-backtracking#p9`).

A backtracking search for complete solutions is equivalent to a depth-first search of the recursion tree (`erickson-backtracking#p3`).

For the sake of efficiency, the summary of past decisions should be as small as possible (`erickson-backtracking#p9`).

In the n queens problem, a recursive call needs the positions of all previously placed queens (`erickson-backtracking#p10`).

In the subset sum problem, a recursive call needs the remaining available integers and the remaining target value, and precisely which elements were previously chosen is unimportant (`erickson-backtracking#p10`).

A backtracking algorithm tries all possibilities for the next decision that are consistent with past decisions (`erickson-backtracking#p10`).

If a subset sums to T, then either it contains the element x or it does not (`erickson-backtracking#p7`).

If T is 0, the elements of the empty subset sum to T, so true is the correct output (`erickson-backtracking#p7`).

Passing a complete copy of the remaining prefix to each recursive call would take Θ(n) time, so the subset sum algorithm passes a reference to the array and the length of the prefix (`erickson-backtracking#p7`).

In the worst case, the recursion tree of the subset sum algorithm is a complete binary tree with depth n, and the algorithm considers all 2^n subsets of X (`erickson-backtracking#p8`).

With minor changes, the subset sum algorithm can count the subsets that sum to a particular value, or choose the best subset that sums to a particular value according to some other criterion (`erickson-backtracking#p8`).

When designing a backtracking algorithm, one should aim for the simplest possible variant of the problem, computing a number or even a single boolean (`erickson-backtracking#p8`).

The first snippet builds all subsets of 1, 2, 3 by choosing, recursing and undoing the choice. It builds all permutations by marking each element as used while it is in the partial result.

```java snippet=m02-l05/SubsetsAndPermutations.java
import java.util.ArrayList;
import java.util.List;

public class SubsetsAndPermutations {
    static void subsets(int[] items, int from, List<Integer> chosen, List<List<Integer>> out) {
        out.add(new ArrayList<>(chosen));
        for (int i = from; i < items.length; i++) {
            chosen.add(items[i]);
            subsets(items, i + 1, chosen, out);
            chosen.remove(chosen.size() - 1);
        }
    }

    static void permutations(int[] items, boolean[] used, List<Integer> chosen, List<List<Integer>> out) {
        if (chosen.size() == items.length) {
            out.add(new ArrayList<>(chosen));
            return;
        }
        for (int i = 0; i < items.length; i++) {
            if (!used[i]) {
                used[i] = true;
                chosen.add(items[i]);
                permutations(items, used, chosen, out);
                chosen.remove(chosen.size() - 1);
                used[i] = false;
            }
        }
    }

    public static void main(String[] args) {
        int[] items = {1, 2, 3};
        List<List<Integer>> subsets = new ArrayList<>();
        subsets(items, 0, new ArrayList<>(), subsets);
        System.out.println("subsets " + subsets);

        List<List<Integer>> permutations = new ArrayList<>();
        permutations(items, new boolean[items.length], new ArrayList<>(), permutations);
        System.out.println("permutations " + permutations.size() + " first " + permutations.get(0)
                + " last " + permutations.get(permutations.size() - 1));
    }
}
```

The subsets are printed as `subsets [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]`.

The permutations are printed as `permutations 6 first [1, 2, 3] last [3, 2, 1]`.

In subset sum, if the target T is negative or the set X is empty, no subset of X sums to T (`erickson-backtracking#p7`).

Leaves of the recursion tree of the n queens algorithm are partial solutions that cannot be extended, either because there is already a queen on every row, or because every position in the next empty row is attacked by an existing queen (`erickson-backtracking#p3`).

The second snippet searches the subsets of 1 to 5 that sum to 5, once with the test that stops when the remaining target is negative and once without it. It counts the recursive calls.

```java snippet=m02-l05/SubsetSumPruning.java
import java.util.ArrayList;
import java.util.List;

public class SubsetSumPruning {
    static int calls;

    static void search(int[] items, int index, int remaining, boolean prune, List<Integer> chosen,
            List<List<Integer>> found) {
        calls++;
        if (remaining == 0) {
            found.add(new ArrayList<>(chosen));
            return;
        }
        if (index == items.length || (prune && remaining < 0)) {
            return;
        }
        chosen.add(items[index]);
        search(items, index + 1, remaining - items[index], prune, chosen, found);
        chosen.remove(chosen.size() - 1);
        search(items, index + 1, remaining, prune, chosen, found);
    }

    public static void main(String[] args) {
        int[] items = {1, 2, 3, 4, 5};

        calls = 0;
        List<List<Integer>> found = new ArrayList<>();
        search(items, 0, 5, true, new ArrayList<>(), found);
        System.out.println("subsets that sum to 5 " + found);
        System.out.println("calls with pruning " + calls);

        calls = 0;
        search(items, 0, 5, false, new ArrayList<>(), new ArrayList<>());
        System.out.println("calls without pruning " + calls);
    }
}
```

It prints `subsets that sum to 5 [[1, 4], [2, 3], [5]]`.

The pruned search makes `calls with pruning 41` and the unpruned search makes `calls without pruning 55`.

The third snippet places one queen in each row of a 4 by 4 board, tries every column for the row, and recurses only when no earlier queen attacks the position. Rows and columns are numbered from 0.

```java snippet=m02-l05/NQueens.java
import java.util.ArrayList;
import java.util.List;

public class NQueens {
    static int calls;

    static void place(int[] columns, int row, List<String> solutions) {
        calls++;
        if (row == columns.length) {
            solutions.add(java.util.Arrays.toString(columns));
            return;
        }
        for (int column = 0; column < columns.length; column++) {
            if (isLegal(columns, row, column)) {
                columns[row] = column;
                place(columns, row + 1, solutions);
            }
        }
    }

    static boolean isLegal(int[] columns, int row, int column) {
        for (int earlier = 0; earlier < row; earlier++) {
            int distance = row - earlier;
            if (columns[earlier] == column || columns[earlier] == column + distance || columns[earlier] == column - distance) {
                return false;
            }
        }
        return true;
    }

    public static void main(String[] args) {
        List<String> solutions = new ArrayList<>();
        place(new int[4], 0, solutions);
        System.out.println("4 queens " + solutions);
        System.out.println("recursive calls " + calls);
    }
}
```

It prints the two solutions as `4 queens [[1, 3, 0, 2], [2, 0, 3, 1]]`, each listing the column of the queen in every row.

The search makes `recursive calls 17`.

## Dynamic programming: state, memoisation and tabulation
<!-- bullets: 2.5.b -->

Dynamic programming is recursion that never solves the same subproblem twice. The subproblems are the different ways the recursive algorithm can call itself, and their answers are stored, often but not always, in an array or table.

The naive recursive algorithm for the Fibonacci numbers is horribly slow (`erickson-dynamic-programming#p3`).

Apart from its recursive calls, the naive Fibonacci algorithm needs only a constant number of steps (`erickson-dynamic-programming#p3`).

Computing F(n) with the naive algorithm takes about twice as long as just counting to F(n) (`erickson-dynamic-programming#p3`).

The running time of the naive recursive Fibonacci algorithm is exponential in n (`erickson-dynamic-programming#p3`).

The reason is that it computes the same Fibonacci numbers over and over and over (`erickson-dynamic-programming#p3`).

Memoisation writes down the results of recursive calls and looks them up again if they are needed later (`erickson-dynamic-programming#p3`).

In a nutshell, dynamic programming is recursion without repetition (`erickson-dynamic-programming#p9`).

Dynamic programming algorithms store the solutions of intermediate subproblems, often but not always in some kind of array or table (`erickson-dynamic-programming#p9`).

Dynamic programming algorithms are best developed in two stages: formulate the problem recursively, then build solutions to the recurrence from the bottom up (`erickson-dynamic-programming#p10`).

A complete recursive formulation has a specification of the problem to solve and a recursive solution in terms of smaller instances of exactly the same problem (`erickson-dynamic-programming#p10`).

The subproblems are all the different ways the recursive algorithm can call itself, starting with some initial input (`erickson-dynamic-programming#p10`).

For the Fibonacci algorithm, the argument of the recursive function is always an integer between 0 and n (`erickson-dynamic-programming#p10`).

Except for the base cases, every subproblem depends on other subproblems (`erickson-dynamic-programming#p11`).

The word programming in dynamic programming does not refer to writing code, but to the older sense of planning or scheduling, typically by filling in a table (`erickson-dynamic-programming#p6`).

In many dynamic programming algorithms, it is not necessary to retain all intermediate results through the entire computation (`erickson-dynamic-programming#p6`).

The Fibonacci algorithm can reduce its space requirements by maintaining only the two newest elements of the array (`erickson-dynamic-programming#p6`).

The snippet counts the calls of a naive recursive Fibonacci and of a version that stores each result in a map.

```java snippet=m02-l05/FibonacciMemoisation.java
import java.util.HashMap;
import java.util.Map;

public class FibonacciMemoisation {
    static long naiveCalls;
    static long memoisedCalls;

    static long naive(int n) {
        naiveCalls++;
        return n < 2 ? n : naive(n - 1) + naive(n - 2);
    }

    static long memoised(int n, Map<Integer, Long> memo) {
        memoisedCalls++;
        if (n < 2) {
            return n;
        }
        Long known = memo.get(n);
        if (known != null) {
            return known;
        }
        long value = memoised(n - 1, memo) + memoised(n - 2, memo);
        memo.put(n, value);
        return value;
    }

    public static void main(String[] args) {
        System.out.println("fib(20) " + naive(20));
        System.out.println("naive calls " + naiveCalls);
        memoised(20, new HashMap<>());
        System.out.println("memoised calls " + memoisedCalls);
    }
}
```

For n = 20 it prints `fib(20) 6765`.

The naive version makes `naive calls 21891` and the memoised version makes `memoised calls 39`.

In text segmentation, each subproblem Splittable(i) depends only on subproblems Splittable(j) with j > i, so the memoised algorithm fills its array in decreasing index order (`erickson-dynamic-programming#p9`).

A memoisation data structure has to store the solution to every subproblem identified, and is usually but not always a multidimensional array (`erickson-dynamic-programming#p11`).

A good evaluation order puts each subproblem after the subproblems it depends on (`erickson-dynamic-programming#p11`).

The number of distinct subproblems determines the space complexity of a memoised algorithm (`erickson-dynamic-programming#p11`).

If the memoisation data structure is an array, the algorithm usually becomes a few nested for-loops around the original recurrence, with the recursive calls replaced by array look-ups (`erickson-dynamic-programming#p11`).

For a fixed string of n letters, there are only n different ways to call the recursive function Splittable(i) in text segmentation, and only O(n^2) different ways to call IsWord(i, j) (`erickson-dynamic-programming#p9`).

The dynamic programming algorithm for text segmentation makes O(n^2) calls to IsWord, an exponential improvement over the backtracking algorithm (`erickson-dynamic-programming#p9`).

The snippet tries to segment `aaaaaaaaaaaab` into the words `a`, `aa` and `aaa`, which is impossible because of the final letter. It counts the word tests of a backtracking search and of a table filled in decreasing index order.

```java snippet=m02-l05/TextSegmentation.java
import java.util.Set;

public class TextSegmentation {
    static final Set<String> WORDS = Set.of("a", "aa", "aaa");
    static int wordTests;

    static boolean isWord(String text, int i, int j) {
        wordTests++;
        return WORDS.contains(text.substring(i, j));
    }

    static boolean backtracking(String text, int i) {
        if (i == text.length()) {
            return true;
        }
        for (int j = i + 1; j <= text.length(); j++) {
            if (isWord(text, i, j) && backtracking(text, j)) {
                return true;
            }
        }
        return false;
    }

    static boolean tabulated(String text) {
        int n = text.length();
        boolean[] splittable = new boolean[n + 1];
        splittable[n] = true;
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i + 1; j <= n; j++) {
                if (isWord(text, i, j) && splittable[j]) {
                    splittable[i] = true;
                }
            }
        }
        return splittable[0];
    }

    public static void main(String[] args) {
        String text = "aaaaaaaaaaaab";
        System.out.println("backtracking " + backtracking(text, 0) + " after " + wordTests + " word tests");
        wordTests = 0;
        System.out.println("table " + tabulated(text) + " after " + wordTests + " word tests");
    }
}
```

The backtracking search prints `backtracking false after 4444 word tests`.

The table prints `table false after 91 word tests`.

## Dynamic programming: common patterns
<!-- bullets: 2.5.b -->

Longest increasing subsequence and edit distance both store their recurrence in an array and fill it in an order in which every entry comes after the entries it depends on. The cost is the number of entries times the work per entry.

Both backtracking algorithms for the longest increasing subsequence can be sped up significantly via dynamic programming (`erickson-dynamic-programming#p13`).

Both backtracking algorithms for the longest increasing subsequence run in O(2^n) time in the worst case (`erickson-dynamic-programming#p13`).

The results of the `LISbigger` subproblems can be memoised in a two-dimensional array, and each subproblem takes O(1) time, not counting recursive calls (`erickson-dynamic-programming#p13`).

Filling the `LISbigger` table one column at a time, from right to left, makes the entries each entry depends on available when it is reached (`erickson-dynamic-programming#p13`).

Each entry `LISfirst[i]` depends only on entries `LISfirst[j]` with j > i, so the array can be filled in decreasing index order (`erickson-dynamic-programming#p15`).

To compute `LISfirst[i]`, the entries `LISfirst[j]` for all indices j > i are considered, in no particular order (`erickson-dynamic-programming#p15`).

Each `LISbigger` subproblem is identified by two indices, so there are only `O(n^2)` distinct recursive subproblems (`erickson-dynamic-programming#p13`).

The array-based dynamic programming algorithm for the longest increasing subsequence runs in `O(n^2)` time and uses `O(n)` space (`erickson-dynamic-programming#p15`).

The edit distance between two strings is the minimum number of letter insertions, letter deletions and letter substitutions required to transform one string into the other (`erickson-dynamic-programming#p15`).

The edit distance between FOOD and MONEY is exactly four (`erickson-dynamic-programming#p15`).

Edit distance is sometimes called Levenshtein distance or Ulam distance (`erickson-dynamic-programming#p15`).

The values of `Edit(i, j)` can be memoised in a two-dimensional array `Edit[0 .. m, 0 .. n]` (`erickson-dynamic-programming#p18`).

Each entry `Edit[i, j]` depends only on its three neighbouring entries `Edit[i-1, j]`, `Edit[i, j-1]` and `Edit[i-1, j-1]` (`erickson-dynamic-programming#p18`).

Filling the `Edit` array row by row from the top down, each row from left to right, makes the entries each entry depends on available when it is reached (`erickson-dynamic-programming#p18`).

The memoisation structure of the edit distance algorithm uses O(mn) space (`erickson-dynamic-programming#p18`).

Each entry of the edit distance array takes O(1) time once its predecessors are known, so the overall algorithm runs in O(mn) time (`erickson-dynamic-programming#p18`).

The snippet fills tables for a 0/1 knapsack with weights 1, 3, 4, 5, values 1, 4, 5, 7 and capacity 7, for the longest increasing subsequence of 3, 1, 4, 1, 5, 9, 2, 6, for the edit distance, and for the paths through a 3 by 3 grid that move only right or down.

```java snippet=m02-l05/TabulatedPatterns.java
public class TabulatedPatterns {
    static int knapsack(int[] weights, int[] values, int capacity) {
        int[] best = new int[capacity + 1];
        for (int item = 0; item < weights.length; item++) {
            for (int c = capacity; c >= weights[item]; c--) {
                best[c] = Math.max(best[c], best[c - weights[item]] + values[item]);
            }
        }
        return best[capacity];
    }

    static int longestIncreasingSubsequence(int[] a) {
        int[] lisFirst = new int[a.length];
        int best = 0;
        for (int i = a.length - 1; i >= 0; i--) {
            lisFirst[i] = 1;
            for (int j = i + 1; j < a.length; j++) {
                if (a[j] > a[i]) {
                    lisFirst[i] = Math.max(lisFirst[i], 1 + lisFirst[j]);
                }
            }
            best = Math.max(best, lisFirst[i]);
        }
        return best;
    }

    static int editDistance(String from, String to) {
        int[][] edit = new int[from.length() + 1][to.length() + 1];
        for (int i = 0; i <= from.length(); i++) {
            edit[i][0] = i;
        }
        for (int j = 0; j <= to.length(); j++) {
            edit[0][j] = j;
        }
        for (int i = 1; i <= from.length(); i++) {
            for (int j = 1; j <= to.length(); j++) {
                int substitution = edit[i - 1][j - 1] + (from.charAt(i - 1) == to.charAt(j - 1) ? 0 : 1);
                edit[i][j] = Math.min(substitution, Math.min(edit[i - 1][j] + 1, edit[i][j - 1] + 1));
            }
        }
        return edit[from.length()][to.length()];
    }

    static long gridPaths(int rows, int columns) {
        long[][] paths = new long[rows][columns];
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < columns; c++) {
                paths[r][c] = r == 0 || c == 0 ? 1 : paths[r - 1][c] + paths[r][c - 1];
            }
        }
        return paths[rows - 1][columns - 1];
    }

    public static void main(String[] args) {
        System.out.println("knapsack " + knapsack(new int[] {1, 3, 4, 5}, new int[] {1, 4, 5, 7}, 7));
        System.out.println("longest increasing subsequence " + longestIncreasingSubsequence(new int[] {3, 1, 4, 1, 5, 9, 2, 6}));
        System.out.println("edit distance " + editDistance("FOOD", "MONEY"));
        System.out.println("grid paths " + gridPaths(3, 3));
    }
}
```

The knapsack table gives `knapsack 9`.

The subsequence table gives `longest increasing subsequence 4`.

The edit distance table gives `edit distance 4` for `FOOD` and `MONEY`.

The grid table gives `grid paths 6`.

## Greedy algorithms
<!-- bullets: 2.5.c -->

A greedy algorithm makes each decision directly, without solving any recursive subproblem. Few optimisation problems are solved correctly this way, and a proof of correctness is what shows that one is.

A greedy algorithm constructs a solution through a series of decisions, like a backtracking algorithm, but makes those decisions directly, without solving any recursive subproblems (`erickson-dynamic-programming#p11`).

Optimization problems that can be solved correctly by a greedy algorithm are quite rare (`erickson-dynamic-programming#p11`).

A greedy proof argues that the optimal choice can be exchanged for the greedy choice without making the solution worse (`erickson-greedy#p7`).

This argument implies by induction that some optimal solution contains the entire greedy solution, and therefore equals the greedy solution (`erickson-greedy#p7`).

If two adjacent files are out of order, swapping them improves the total cost (`erickson-greedy#p3`).

An edge is safe if it is the minimum-weight edge with exactly one endpoint in some component of the intermediate spanning forest F (`erickson-mst#p3`).

To choose the largest set of classes that do not conflict, the greedy algorithm scans the classes in order of finish time and takes each class that does not conflict with the latest class taken (`erickson-greedy#p4`).

After the initial sort, the greedy class schedule is a linear-time loop, so the whole algorithm runs in O(n log n) time (`erickson-greedy#p4`).

Evaluating the recursive solution for class scheduling from the bottom up gives a dynamic programming algorithm that runs in O(n^3) time (`erickson-greedy#p4`).

At least one maximal conflict-free schedule includes the class that finishes first (`erickson-greedy#p5`).

The greedy schedule is not claimed to be the only maximal schedule, only that at least one of the optimal schedules is the one the greedy algorithm produces (`erickson-greedy#p5`).

The snippet schedules four classes (1 to 10), (2 to 3), (4 to 5) and (6 to 7), once by earliest start and once by earliest finish. It also fills the knapsack of the previous section greedily, by value per weight.

```java snippet=m02-l05/GreedyChoices.java
import java.util.Arrays;
import java.util.Comparator;

public class GreedyChoices {
    static int scheduled(int[][] classes, Comparator<int[]> order) {
        int[][] sorted = classes.clone();
        Arrays.sort(sorted, order);
        int count = 0;
        int lastFinish = Integer.MIN_VALUE;
        for (int[] c : sorted) {
            if (c[0] >= lastFinish) {
                count++;
                lastFinish = c[1];
            }
        }
        return count;
    }

    static int greedyKnapsack(int[] weights, int[] values, int capacity) {
        Integer[] byRatio = new Integer[weights.length];
        for (int i = 0; i < byRatio.length; i++) {
            byRatio[i] = i;
        }
        Arrays.sort(byRatio, Comparator.comparingDouble((Integer i) -> (double) values[i] / weights[i]).reversed());
        int total = 0;
        for (int i : byRatio) {
            if (weights[i] <= capacity) {
                capacity -= weights[i];
                total += values[i];
            }
        }
        return total;
    }

    public static void main(String[] args) {
        int[][] classes = {{1, 10}, {2, 3}, {4, 5}, {6, 7}};
        System.out.println("earliest start " + scheduled(classes, Comparator.comparingInt(c -> c[0])));
        System.out.println("earliest finish " + scheduled(classes, Comparator.comparingInt(c -> c[1])));
        System.out.println("greedy knapsack " + greedyKnapsack(new int[] {1, 3, 4, 5}, new int[] {1, 4, 5, 7}, 7));
    }
}
```

Choosing by earliest start prints `earliest start 1`.

Choosing by earliest finish prints `earliest finish 3`.

The greedy knapsack prints `greedy knapsack 8`, while the table above found 9.

## Basic bit manipulation
<!-- bullets: 2.5.d -->

Bit methods work on the binary form of an int. `Integer` has methods to count, find and isolate bits. `Math.floorMod` gives a remainder with the sign of the divisor. A `BitSet` holds a vector of bits that grows as needed.

`Integer.bitCount` returns the number of one-bits in the two's complement binary representation of an int value (`javadoc-integer#bitCount(int)`).

`Integer.highestOneBit` returns an int value with at most a single one-bit, in the position of the highest-order one-bit of its argument (`javadoc-integer#highestOneBit(int)`).

`Integer.numberOfTrailingZeros` returns 32 if its argument is zero (`javadoc-integer#numberOfTrailingZeros(int)`).

`Integer.lowestOneBit` returns an int value with at most a single one-bit, in the position of the lowest-order one-bit of its argument, and zero if the argument is zero (`javadoc-integer#lowestOneBit(int)`).

`Integer.numberOfLeadingZeros` returns the number of zero bits preceding the highest-order one-bit, and 32 if its argument is zero (`javadoc-integer#numberOfLeadingZeros(int)`).

For all positive int values x, `floor(log2(x))` equals `31 - numberOfLeadingZeros(x)` (`javadoc-integer#numberOfLeadingZeros(int)`).

`Integer.rotateLeft` makes the bits shifted out of the high-order side reenter on the low-order side (`javadoc-integer#rotateLeft(int,int)`).

The first snippet applies the three methods and tests for a power of two with `n & (n - 1)`.

```java snippet=m02-l05/BitOperations.java
public class BitOperations {
    public static void main(String[] args) {
        System.out.println("ones in 11: " + Integer.bitCount(11));
        System.out.println("highest one-bit of 100: " + Integer.highestOneBit(100));
        System.out.println("trailing zeros of 40: " + Integer.numberOfTrailingZeros(40));
        System.out.println("64 is a power of two: " + ((64 & (64 - 1)) == 0));
        System.out.println("48 is a power of two: " + ((48 & (48 - 1)) == 0));
    }
}
```

The count of one-bits in 11 is printed as `ones in 11: 3`, because 11 is 1011 in binary.

The highest one-bit of 100 is printed as `highest one-bit of 100: 64`.

The trailing zeros of 40 are printed as `trailing zeros of 40: 3`, because 40 is 101000 in binary.

The power-of-two tests print `64 is a power of two: true` and `48 is a power of two: false`.

`Math.floorMod` returns a result with the same sign as the divisor y, or zero (`javadoc-math#floorMod(int,int)`).

`floorMod(-4, +3)` is +2, while `-4 % +3` is -1 (`javadoc-math#floorMod(int,int)`).

The relationship between `floorDiv` and `floorMod` is that `floorDiv(x, y) * y + floorMod(x, y) == x` (`javadoc-math#floorMod(int,int)`).

`floorMod(x, y)` is zero exactly when `x % y` is zero as well (`javadoc-math#floorMod(int,int)`).

If neither `floorMod(x, y)` nor `x % y` is zero, they differ exactly when the signs of the arguments differ (`javadoc-math#floorMod(int,int)`).

A `BitSet` implements a vector of bits that grows as needed (`javadoc-bitset#class-bitset`).

By default, all bits in a `BitSet` initially have the value false (`javadoc-bitset#class-bitset`).

A `BitSet` is not safe for multithreaded use without external synchronization (`javadoc-bitset#class-bitset`).

`BitSet.nextSetBit` returns the index of the first bit set to true that occurs on or after the specified starting index, or -1 if no such bit exists (`javadoc-bitset#nextSetBit(int)`).

`BitSet.cardinality` returns the number of bits set to true in the bit set (`javadoc-bitset#cardinality()`).

`BitSet.flip` sets the bit at the specified index to the complement of its current value (`javadoc-bitset#flip(int)`).

It prints `floor modulus of -4 and 3: 2` and `remainder of -4 and 3: -1`.

The third snippet applies `lowestOneBit`, `numberOfLeadingZeros`, `rotateLeft`, `floorDiv` and `floorMod`. It then walks a `BitSet` with bits 1, 3 and 5 set using `nextSetBit`, flips bit 3 and asks for the cardinality.

```java snippet=m02-l05/BitTricks.java
import java.util.BitSet;

public class BitTricks {
    public static void main(String[] args) {
        System.out.println("lowest one-bit of 40: " + Integer.lowestOneBit(40));
        System.out.println("leading zeros of 40: " + Integer.numberOfLeadingZeros(40));
        System.out.println("floor of log base 2 of 40: " + (31 - Integer.numberOfLeadingZeros(40)));
        System.out.println("highest bit rotated left by one: " + Integer.rotateLeft(1 << 31, 1));
        System.out.println("floor division and floor modulus of -4 by 3: " + Math.floorDiv(-4, 3) + " " + Math.floorMod(-4, 3));

        BitSet bits = new BitSet();
        bits.set(1);
        bits.set(3);
        bits.set(5);
        StringBuilder indices = new StringBuilder();
        for (int i = bits.nextSetBit(0); i >= 0; i = bits.nextSetBit(i + 1)) {
            indices.append(i).append(' ');
        }
        System.out.println("set bits " + indices.toString().trim());
        bits.flip(3);
        System.out.println("cardinality after the flip " + bits.cardinality());
        System.out.println("next set bit from 6: " + bits.nextSetBit(6));
    }
}
```

For 40 it prints `lowest one-bit of 40: 8` and `leading zeros of 40: 26`, and the logarithm line prints `floor of log base 2 of 40: 5`.

Rotating the highest bit left by one prints `highest bit rotated left by one: 1`.

The division and modulus of -4 by 3 print `floor division and floor modulus of -4 by 3: -2 2`.

The loop over the `BitSet` prints `set bits 1 3 5`, and after flipping bit 3 it prints `cardinality after the flip 2`.

With no set bit at or after index 6, it prints `next set bit from 6: -1`.

## Key points

- A recursive method needs a base case, and the recursive reductions must lead to it.
- Backtracking makes one decision per recursive call, consistent with all previous decisions, and a search for complete solutions is a depth-first search of the recursion tree.
- Peasant multiplication reached the base case after 5 calls for 13 x 25, and the 4 queens search found 2 solutions in 17 recursive calls.
- Stopping a branch when the remaining target is negative cut the calls for the subsets of 1 to 5 from 55 to 41.
- Dynamic programming is recursion without repetition: it stores the solutions of intermediate subproblems.
- The naive Fibonacci recursion made 21891 calls for n = 20 and the memoised version made 39.
- A table filled in decreasing index order made 91 word tests where the backtracking search made 4444 for the same text segmentation.
- The edit distance algorithm fills an `Edit` array of size (m + 1) by (n + 1) in O(mn) space and time, and each entry depends on its three neighbours.
- The array-based dynamic programming algorithm for the longest increasing subsequence runs in `O(n^2)` time and uses `O(n)` space.
- Greedy algorithms make decisions directly, and problems they solve correctly are quite rare; the exchange argument is the proof technique.
- Greedy by value per weight gave 8 on the knapsack where the table gave 9, and earliest start scheduled 1 class where earliest finish scheduled 3.
- The greedy class schedule scans the classes in order of finish time and runs in O(n log n) time, against O(n^3) for the dynamic programming algorithm.
- `Integer.bitCount` counts the one-bits of an int in its two's complement representation, `highestOneBit` returns a value with at most a single one-bit, and `numberOfTrailingZeros` returns 32 for zero.
- `Math.floorMod` has the sign of the divisor, so `floorMod(-4, 3)` is 2 while `-4 % 3` is -1.
- `floorMod(x, y)` and `x % y` differ exactly when neither is zero and the signs of the arguments differ.
- `BitSet.nextSetBit` returns -1 when no set bit exists on or after the index.
