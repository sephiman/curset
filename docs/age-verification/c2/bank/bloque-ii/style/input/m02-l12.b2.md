- a) En versiones separadas de cada portal para móviles, tabletas y ordenadores, con contenidos duplicados
- b) En duplicar el trabajo y el mantenimiento de cada contenido por dispositivo
- c) En estándares web como HTML5 y CSS3, unidades relativas, media queries y frameworks  ✓
- d) En estándares cerrados de cada fabricante de navegadores y plugins como Flash y PDF
Cita: fuente: `euskadi-diseno-adaptable.html`; «Diseño adaptable (Responsive Design)»
Explicación: La adaptabilidad de los portales se basa en estándares web (HTML5 y CSS3), unidades relativas, media queries, lenguajes de script y frameworks como Bootstrap. Hacer versiones separadas por dispositivo es justo lo que el diseño adaptable evita. La página basa la adaptabilidad en estándares web, no en estándares cerrados de cada fabricante. Duplicar el trabajo y el mantenimiento es lo que se evita al no hacer versiones extra para determinados entornos.

## m02-l12-q116
¿Cuál de las siguientes situaciones describía el tráfico de Internet en los primeros años de su expansión, según el Servicio Web del Gobierno Vasco?
- a) Casi todo se realizaba desde ordenadores personales, con pocos sistemas operativos y navegadores  ✓
- b) Se repartía por igual entre ordenadores, televisores y consolas con navegador
- c) Casi todo se realizaba desde teléfonos inteligentes, con muchos sistemas operativos
- d) Casi todo se realizaba desde tabletas, con una gran variedad de resoluciones
Cita: fuente: `euskadi-diseno-adaptable.html`; «Diseño adaptable (Responsive Design)»
Explicación: En los primeros años casi todo el tráfico se realizaba desde ordenadores personales, con un número reducido de sistemas operativos, navegadores, resoluciones y dispositivos de entrada. Los teléfonos inteligentes llegaron después y cambiaron ese panorama. Los televisores y las consolas con navegador integrado son un fenómeno posterior, con la irrupción de nuevos dispositivos. Con las tabletas y otros dispositivos aumentó la variedad de resoluciones, tras los primeros años.

## m02-l12-q117
Según la introducción del estándar HTML del WHATWG, ¿qué atributos permiten incluir datos para scripts del cliente o del servidor, y los navegadores nunca los tocan?
- a) Los atributos class, que sirven para crear elementos propios
- b) Los atributos de manejadores de eventos, que ejecutan los scripts
- c) Los atributos href, que fijan el destino de un enlace
- d) Los atributos data-*, que buscan y procesan los scripts  ✓
Cita: fuente: `whatwg-html-introduccion.html`; «1.7.2 Extensibility»
Explicación: Los atributos data-* permiten a los scripts incluir datos en los elementos HTML, y se garantiza que los navegadores nunca los tocan. El atributo class sirve para extender elementos y crear elementos propios, no para guardar datos de scripts. El atributo href fija el destino de un enlace, que un script puede cambiar. Los atributos de contenido de manejadores de eventos sirven para incrustar un script, no para guardar datos de scripts.

## m02-l12-q118
¿Cuál de las siguientes definiciones corresponde a una cookie, según el glosario de términos de ciberseguridad de INCIBE?
- a) Un número único que identifica a todo sistema conectado a una red
- b) Un servicio que asocia cada nombre de dominio con información sobre él
- c) Un programa que monitoriza la información que circula por la red
- d) Un pequeño fichero que un sitio web guarda en el equipo del usuario  ✓
Cita: fuente: `incibe-glosario-ciberseguridad.pdf`; «2.3.29. Cookie»
Explicación: Una cookie es un pequeño fichero que almacena información enviada por un sitio web y que se guarda en el equipo del usuario, de modo que el sitio puede consultar su actividad previa. El número único que identifica a todo sistema conectado a una red es la dirección IP. El programa que monitoriza la información que circula por la red es un sniffer. El servicio que asocia cada nombre de dominio con información sobre él es el DNS.

## m02-l12-q119
Según el glosario de INCIBE, ¿dónde se almacena una cookie, que es información enviada por un sitio web?
- a) En el equipo del usuario, para que el sitio web consulte su actividad  ✓
- b) En el servidor DNS, junto con la información del nombre de dominio
- c) En el servidor del sitio web, que la envía de nuevo al navegador cuando se pide
- d) En el router de la red local, que la comparte con todos los equipos
Cita: fuente: `incibe-glosario-ciberseguridad.pdf`; «2.3.29. Cookie»
Explicación: La cookie se almacena en el equipo del usuario, de manera que el sitio web puede consultar la actividad previa del usuario. La cookie no se guarda en el servidor del sitio web: se almacena en el equipo del usuario. El servidor DNS asocia nombres de dominio con información; no guarda las cookies. El glosario sitúa la cookie en el equipo del usuario, no en el router de la red local.

## m02-l12-q120
Señale la ventaja que ofrece al usuario una cookie cuando introduce su nombre de usuario y contraseña, según el glosario de INCIBE:
- a) Distinguir si quien entra en la página es un humano o un bot
- b) Cifrar la información que viaja entre su navegador y el servidor
- c) Traducir el nombre de la página en una dirección IP
- d) No tener que introducirlos para cada página del servidor  ✓
Cita: fuente: `incibe-glosario-ciberseguridad.pdf`; «2.3.29. Cookie»
Explicación: Entre las funciones de la cookie está llevar el control de usuarios: al introducir el usuario y la contraseña se almacena una cookie para no tener que introducirlos en cada página del servidor. Cifrar la información entre navegador y servidor es lo que hace HTTPS. Distinguir a un humano de un bot es la función del CAPTCHA. Traducir nombres en direcciones IP es la función del DNS.
