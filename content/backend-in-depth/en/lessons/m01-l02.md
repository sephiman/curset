## Creational patterns

According to the course's registered chapter lists, Design Patterns covers creational patterns in chapter 3, "Creational Patterns", and Effective Java covers creating and destroying objects in chapter 2, "Creating and Destroying Objects".

The snippet builds an `Invoice` through a builder whose `build` method checks the required fields before it constructs the object.

```java snippet=m01-l02/BuilderInvariants.java
public class BuilderInvariants {
    static final class Invoice {
        private final String number;
        private final long cents;

        private Invoice(Builder builder) {
            this.number = builder.number;
            this.cents = builder.cents;
        }

        static Builder builder() {
            return new Builder();
        }

        @Override
        public String toString() {
            return "Invoice " + number + " " + cents;
        }

        static final class Builder {
            private String number;
            private long cents = -1;

            Builder number(String number) {
                this.number = number;
                return this;
            }

            Builder cents(long cents) {
                this.cents = cents;
                return this;
            }

            Invoice build() {
                if (number == null || number.isBlank()) {
                    throw new IllegalStateException("number is required");
                }
                if (cents < 0) {
                    throw new IllegalStateException("cents must not be negative");
                }
                return new Invoice(this);
            }
        }
    }

    public static void main(String[] args) {
        System.out.println(Invoice.builder().number("F-1").cents(1200).build());
        try {
            Invoice.builder().number("F-2").build();
        } catch (IllegalStateException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

The snippet prints `Invoice F-1 1200` for the complete builder.

It prints `cents must not be negative` for the builder that never set `cents`, because `build` throws an `IllegalStateException` before any `Invoice` exists.

## Structural patterns and proxies
<!-- bullets: 1.2.b -->

:::judgement{source="Gamma, Helm, Johnson and Vlissides, Design Patterns, 1st edition (1994)"}
According to the course's registered chapter list, Design Patterns covers structural patterns in chapter 4, "Structural Patterns".
:::

`Proxy` provides static methods for creating objects that act like instances of interfaces but allow for customized method invocation (`javadoc-proxy#class-proxy`).

A proxy class is a class created at runtime that implements a specified list of interfaces, known as proxy interfaces (`javadoc-proxy#class-proxy`).

A proxy instance is an instance of a proxy class (`javadoc-proxy#class-proxy`).

Each proxy instance has an associated invocation handler object, which implements the interface `InvocationHandler` (`javadoc-proxy#class-proxy`).

A method invocation on a proxy instance through one of its proxy interfaces is dispatched to the `invoke` method of the instance's invocation handler (`javadoc-proxy#class-proxy`).

The `invoke` method receives the proxy instance, a `java.lang.reflect.Method` object identifying the method that was invoked, and an array of type `Object` containing the arguments (`javadoc-proxy#class-proxy`).

A proxy class is final and non-abstract (`javadoc-proxy#class-proxy`).

A proxy class extends `java.lang.reflect.Proxy` (`javadoc-proxy#class-proxy`).

A proxy class implements exactly the interfaces specified at its creation, in the same order (`javadoc-proxy#class-proxy`).

For a proxy instance `proxy` and an interface `Foo` implemented by its proxy class, `proxy instanceof Foo` returns true and the cast `(Foo) proxy` succeeds (`javadoc-proxy#class-proxy`).

An invocation of the `hashCode`, `equals` or `toString` methods declared in `java.lang.Object` on a proxy instance is dispatched to the handler's `invoke` method in the same manner as an interface method invocation (`javadoc-proxy#class-proxy`).

The snippet creates a JDK dynamic proxy of a `Greeter` interface whose handler records each call and forwards `greet` to a target.

```java snippet=m01-l02/ProxyDispatch.java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Modifier;
import java.lang.reflect.Proxy;
import java.util.ArrayList;
import java.util.List;

public class ProxyDispatch {
    interface Greeter {
        String greet(String name);
    }

    public static void main(String[] args) {
        Greeter target = name -> "hello " + name;
        List<String> calls = new ArrayList<>();
        InvocationHandler handler = (proxy, method, arguments) -> {
            calls.add(method.getDeclaringClass().getSimpleName() + "." + method.getName());
            if (method.getName().equals("toString")) {
                return "proxy";
            }
            return method.invoke(target, arguments);
        };
        Greeter greeter = (Greeter) Proxy.newProxyInstance(
                Greeter.class.getClassLoader(), new Class<?>[] {Greeter.class}, handler);
        System.out.println(greeter.greet("Ana"));
        System.out.println(greeter);
        System.out.println(calls);
        System.out.println(Proxy.isProxyClass(greeter.getClass()));
        System.out.println(Modifier.isFinal(greeter.getClass().getModifiers()));
        System.out.println(greeter.getClass().getSuperclass().getName());
    }
}
```

The snippet prints `hello Ana`, which the handler returned from the target, and `proxy`, which the handler returned for `toString`.

It prints `[Greeter.greet, Object.toString]`, so the handler saw the interface method and the `Object` method alike.

It prints `true` for `Proxy.isProxyClass`, `true` for the `final` modifier of the proxy class, and `java.lang.reflect.Proxy` as the name of its superclass.

Spring AOP uses either JDK dynamic proxies or CGLIB to create the proxy for a given target object (`spring-fw-aop-proxying#proxying-mechanisms`).

JDK dynamic proxies are built into the JDK, whereas CGLIB is a common open-source class definition library repackaged into `spring-core` (`spring-fw-aop-proxying#proxying-mechanisms`).

If the target object to be proxied implements at least one interface, a JDK dynamic proxy is used, and all of the interfaces implemented by the target type are proxied (`spring-fw-aop-proxying#proxying-mechanisms`).

If the target object does not implement any interfaces, a CGLIB proxy is created, which is a runtime-generated subclass of the target type (`spring-fw-aop-proxying#proxying-mechanisms`).

When CGLIB proxying is forced, `final` classes cannot be proxied, because they cannot be extended (`spring-fw-aop-proxying#proxying-mechanisms`).

When CGLIB proxying is forced, `final` methods and `private` methods cannot be advised, because they cannot be overridden (`spring-fw-aop-proxying#proxying-mechanisms`).

:::esquema{kind=tabla title="Proxy mechanisms behind Spring AOP"}
| Mechanism | Used when | What the proxy is | Source |
|---|---|---|---|
| JDK dynamic proxy | The target implements at least one interface | An object that implements the target's interfaces and dispatches calls to an invocation handler | `spring-fw-aop-proxying#proxying-mechanisms`; `javadoc-proxy#class-proxy` |
| CGLIB proxy | The target implements no interface | A runtime-generated subclass of the target type | `spring-fw-aop-proxying#proxying-mechanisms` |
:::

## Behavioural patterns
<!-- bullets: 1.2.c -->

:::judgement{source="Gamma, Helm, Johnson and Vlissides, Design Patterns, 1st edition (1994)"}
According to the course's registered chapter list, Design Patterns covers behavioural patterns in chapter 5, "Behavioral Patterns".

The snippet gives a `Checkout` a discount function chosen by its caller and a list of listeners that are told the total.

```java snippet=m01-l02/StrategyObserver.java
import java.util.ArrayList;
import java.util.List;
import java.util.function.Consumer;
import java.util.function.LongUnaryOperator;

public class StrategyObserver {
    static final class Checkout {
        private final LongUnaryOperator discount;
        private final List<Consumer<Long>> listeners = new ArrayList<>();

        Checkout(LongUnaryOperator discount) {
            this.discount = discount;
        }

        void subscribe(Consumer<Long> listener) {
            listeners.add(listener);
        }

        long pay(long cents) {
            long total = discount.applyAsLong(cents);
            listeners.forEach(listener -> listener.accept(total));
            return total;
        }
    }

    public static void main(String[] args) {
        Checkout half = new Checkout(cents -> cents / 2);
        half.subscribe(total -> System.out.println("audit " + total));
        half.subscribe(total -> System.out.println("mail " + total));
        System.out.println(half.pay(1000));
        System.out.println(new Checkout(cents -> cents).pay(1000));
    }
}
```

The snippet prints `audit 500` and `mail 500` first, one per listener in subscription order, and then `500`, the value `pay` returned for the halving discount.

It prints `1000` for the checkout built with the identity discount, which has no listeners.

## Key points

- A JDK proxy class is created at runtime, implements the proxy interfaces, is final and extends `java.lang.reflect.Proxy` (`javadoc-proxy#class-proxy`).
- A call on a proxy instance reaches the `invoke` method of its invocation handler, and so do `hashCode`, `equals` and `toString` (`javadoc-proxy#class-proxy`).
- Spring AOP uses a JDK dynamic proxy when the target implements at least one interface, and a CGLIB runtime-generated subclass when it implements none (`spring-fw-aop-proxying#proxying-mechanisms`).
- With CGLIB proxying, `final` classes cannot be proxied and `final` and `private` methods cannot be advised (`spring-fw-aop-proxying#proxying-mechanisms`).
- The snippet's builder throws an `IllegalStateException` from `build` when `cents` was never set, so no `Invoice` is constructed.
