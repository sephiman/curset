# Java Streams, gatherers and collections in depth

## Flattening, prefixes and reducing
<!-- bullets: 11.1.a -->

`flatMap` replaces each element of a stream with the contents of a mapped stream produced by applying the provided mapping function to each element (`javadoc-stream#flatMap(java.util.function.Function)`).

If a mapped stream is null, `flatMap` uses an empty stream instead (`javadoc-stream#flatMap(java.util.function.Function)`).

Each stream produced by the mapping function of `flatMap` is closed after its contents have been placed into the resulting stream (`javadoc-stream#flatMap(java.util.function.Function)`).

`flatMap` applies a one-to-many transformation to the elements of the stream and then flattens the resulting elements into a new stream (`javadoc-stream#flatMap(java.util.function.Function)`).

On an ordered stream, `takeWhile` returns the longest prefix of elements that match the predicate (`javadoc-stream#takeWhile(java.util.function.Predicate)`).

On an ordered stream, `dropWhile` returns the remaining elements after dropping the longest prefix of elements that match the predicate (`javadoc-stream#dropWhile(java.util.function.Predicate)`).

The longest prefix of an ordered stream starts at the first element of the stream, and the element immediately following it does not match the predicate (`javadoc-stream#takeWhile(java.util.function.Predicate)`).

If some but not all elements of an unordered stream match the predicate, the behavior of `takeWhile` is nondeterministic (`javadoc-stream#takeWhile(java.util.function.Predicate)`).

`takeWhile` is a short-circuiting stateful intermediate operation (`javadoc-stream#takeWhile(java.util.function.Predicate)`).

`dropWhile` is a stateful intermediate operation (`javadoc-stream#dropWhile(java.util.function.Predicate)`).

`takeWhile` can be quite expensive on ordered parallel pipelines, because it must return the longest prefix of elements in the encounter order (`javadoc-stream#takeWhile(java.util.function.Predicate)`).

The snippet flattens three lists, then applies `filter`, `takeWhile` and `dropWhile` with the same predicate to the elements 1, 2, 5, 1 and 6, and finally reduces 1 to 4 with an identity of 10.

```java snippet=m11-l01/PrefixSteps.java
import java.util.List;
import java.util.stream.Stream;

public class PrefixSteps {
    public static void main(String[] args) {
        List<List<Integer>> nested = List.of(List.of(1, 2), List.of(), List.of(3));
        System.out.println(nested.stream().flatMap(List::stream).toList());
        System.out.println(Stream.of(1, 2, 5, 1, 6).filter(n -> n < 3).toList());
        System.out.println(Stream.of(1, 2, 5, 1, 6).takeWhile(n -> n < 3).toList());
        System.out.println(Stream.of(1, 2, 5, 1, 6).dropWhile(n -> n < 3).toList());
        System.out.println(Stream.of(1, 2, 3, 4).reduce(10, Integer::sum));
    }
}
```

The snippet prints `[1, 2, 3]` for the flattened lists `[1, 2]`, `[]` and `[3]`.

It prints `[1, 2, 1]` for `filter(n -> n < 3)`, because `filter` tests every element.

It prints `[1, 2]` for `takeWhile(n -> n < 3)`, because the stream stops at the first element that fails the predicate.

It prints `[5, 1, 6]` for `dropWhile(n -> n < 3)`, because the `1` after the `5` is kept.

It prints `20` for `reduce(10, Integer::sum)` over 1, 2, 3 and 4, because the identity is the starting value.

`reduce` takes an identity value and an associative accumulation function and returns the reduced value (`javadoc-stream#reduce(java.lang.Object,java.util.function.BinaryOperator)`).

The identity value of `reduce` must be an identity for the accumulator: for all `t`, `accumulator.apply(identity, t)` is equal to `t` (`javadoc-stream#reduce(java.lang.Object,java.util.function.BinaryOperator)`).

A reduction operation, also called a fold, combines a sequence of input elements into a single summary result by repeated application of a combining operation (`javadoc-stream-package#Reduction`).

A properly constructed reduce operation is inherently parallelizable, so long as the functions that process the elements are associative and stateless (`javadoc-stream-package#Reduction`).

In the three-argument form of `reduce`, the identity element is both an initial seed value and a default result if there are no input elements (`javadoc-stream-package#Reduction`).

In the three-argument form of `reduce`, the combiner function combines two partial results to produce a new partial result (`javadoc-stream-package#Reduction`).

The combiner is necessary in parallel reductions, where the input is partitioned, a partial accumulation is computed for each partition, and the partial results are combined (`javadoc-stream-package#Reduction`).

The three-argument form of `reduce` generalizes the two-argument form by incorporating a mapping step into the accumulation step (`javadoc-stream-package#Reduction`).

## Composed comparators
<!-- bullets: 11.1.a -->

`thenComparing(other)` returns a lexicographic-order comparator: if this comparator considers two elements equal, `other` determines the order (`javadoc-comparator#thenComparing(java.util.Comparator)`).

`Comparator.comparing(keyExtractor, keyComparator)` compares by the extracted sort key using the specified comparator (`javadoc-comparator#comparing(java.util.function.Function,java.util.Comparator)`).

`Comparator.nullsFirst` returns a null-friendly comparator that considers null to be less than non-null (`javadoc-comparator#nullsFirst(java.util.Comparator)`).

When both values are null, the comparator from `nullsFirst` considers them equal (`javadoc-comparator#nullsFirst(java.util.Comparator)`).

If both values are non-null, the comparator from `nullsFirst` uses the specified comparator to determine the order (`javadoc-comparator#nullsFirst(java.util.Comparator)`).

If the comparator given to `nullsFirst` is null, the returned comparator considers all non-null values to be equal (`javadoc-comparator#nullsFirst(java.util.Comparator)`).

The snippet sorts four people by city and then by name. The first comparator puts null cities first and ignores the case of names. The second puts null cities last and compares names in their natural order.

```java snippet=m11-l01/ComposedComparators.java
import java.util.Comparator;
import java.util.List;
import java.util.stream.Stream;

public class ComposedComparators {
    record Person(String name, String city) {}

    public static void main(String[] args) {
        List<Person> people = List.of(
                new Person("Zed", "Lyon"),
                new Person("amy", "Lyon"),
                new Person("Cid", null),
                new Person("Dee", "Oslo"));

        Comparator<Person> nullsFirst = Comparator
                .comparing(Person::city, Comparator.nullsFirst(Comparator.naturalOrder()))
                .thenComparing(Person::name, String.CASE_INSENSITIVE_ORDER);
        Comparator<Person> nullsLast = Comparator
                .comparing(Person::city, Comparator.nullsLast(Comparator.<String>naturalOrder()))
                .thenComparing(Person::name);

        System.out.println(names(people.stream().sorted(nullsFirst)));
        System.out.println(names(people.stream().sorted(nullsLast)));
    }

    private static List<String> names(Stream<Person> sorted) {
        return sorted.map(Person::name).toList();
    }
}
```

The snippet prints `[Cid, amy, Zed, Dee]` for the first comparator.

It prints `[Zed, amy, Dee, Cid]` for the second comparator.

## Collectors that group, partition, merge and tee
<!-- bullets: 11.1.b -->

`groupingBy` implements a cascaded "group by" operation: it groups elements according to a classification function and then reduces the values of each key with the downstream collector (`javadoc-collectors#groupingBy(java.util.function.Function,java.util.function.Supplier,java.util.stream.Collector)`).

The map produced by `groupingBy` is created with the supplied factory function (`javadoc-collectors#groupingBy(java.util.function.Function,java.util.function.Supplier,java.util.stream.Collector)`).

The collector returned by `groupingBy` is not concurrent (`javadoc-collectors#groupingBy(java.util.function.Function,java.util.function.Supplier,java.util.stream.Collector)`).

In a parallel pipeline, the combiner of `groupingBy` merges the keys of one map into another, which can be an expensive operation (`javadoc-collectors#groupingBy(java.util.function.Function,java.util.function.Supplier,java.util.stream.Collector)`).

`partitioningBy` reduces the values of each partition with a downstream collector and organizes them into a `Map<Boolean, D>` (`javadoc-collectors#partitioningBy(java.util.function.Predicate,java.util.stream.Collector)`).

The map returned by `partitioningBy` always contains mappings for both `false` and `true` keys (`javadoc-collectors#partitioningBy(java.util.function.Predicate,java.util.stream.Collector)`).

There are no guarantees on the type, mutability, serializability or thread-safety of the map returned by `partitioningBy` (`javadoc-collectors#partitioningBy(java.util.function.Predicate,java.util.stream.Collector)`).

If a partition has no elements, its value is obtained by calling the supplier function of the downstream collector and then applying its finisher function (`javadoc-collectors#partitioningBy(java.util.function.Predicate,java.util.stream.Collector)`).

The snippet groups six words by first letter and then by length, partitions them by length, and partitions an empty stream.

```java snippet=m11-l01/CollectorGrouping.java
import static java.util.stream.Collectors.counting;
import static java.util.stream.Collectors.groupingBy;
import static java.util.stream.Collectors.partitioningBy;

import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Stream;

public class CollectorGrouping {
    public static void main(String[] args) {
        List<String> words = List.of("apple", "avocado", "banana", "blueberry", "cherry", "apple");

        Map<Character, Map<Integer, Long>> byLetterThenLength = words.stream().collect(
                groupingBy(w -> w.charAt(0), TreeMap::new,
                        groupingBy(String::length, TreeMap::new, counting())));
        System.out.println(byLetterThenLength);

        Map<Boolean, Long> longOrShort = words.stream().collect(partitioningBy(w -> w.length() > 6, counting()));
        System.out.println(longOrShort);

        Map<Boolean, Long> noWords = Stream.<String>empty().collect(partitioningBy(w -> true, counting()));
        System.out.println(noWords);
    }
}
```

The snippet prints `{a={5=2, 7=1}, b={6=1, 9=1}, c={6=1}}` for the two-level grouping, with the counts as the innermost values.

It prints `{false=4, true=2}` for the partition by length, because four words have six letters or fewer.

It prints `{false=0, true=0}` for the empty stream, because both partitions are counted by the downstream collector.

If the mapped keys contain duplicates according to `Object.equals`, `toMap` applies the value mapping function to each equal element and merges the results with the provided merging function (`javadoc-collectors#toMap(java.util.function.Function,java.util.function.Function,java.util.function.BinaryOperator)`).

The other forms of `toMap` use a merge function that throws unconditionally (`javadoc-collectors#toMap(java.util.function.Function,java.util.function.Function,java.util.function.BinaryOperator)`).

The merge function of `toMap` resolves collisions between values associated with the same key (`javadoc-collectors#toMap(java.util.function.Function,java.util.function.Function,java.util.function.BinaryOperator)`).

There are no guarantees on the type, mutability, serializability or thread-safety of the map returned by `toMap` (`javadoc-collectors#toMap(java.util.function.Function,java.util.function.Function,java.util.function.BinaryOperator)`).

`teeing` returns a collector that is a composite of two downstream collectors (`javadoc-collectors#teeing(java.util.stream.Collector,java.util.stream.Collector,java.util.function.BiFunction)`).

Every element passed to the collector from `teeing` is processed by both downstream collectors, and their results are merged with the specified merge function (`javadoc-collectors#teeing(java.util.stream.Collector,java.util.stream.Collector,java.util.function.BiFunction)`).

A mutable reduction operation accumulates input elements into a mutable result container, such as a `Collection` or `StringBuilder`, as it processes the elements (`javadoc-stream-package#MutableReduction`).

A `collect` operation requires a supplier function, an accumulator function and a combining function (`javadoc-stream-package#MutableReduction`).

Concatenating strings with `reduce("", String::concat)` does a great deal of string copying, and its run time is O(n^2) in the number of characters (`javadoc-stream-package#MutableReduction`).

Packaging mutable reductions into a `Collector` makes them composable (`javadoc-stream-package#MutableReduction`).

For any partially accumulated result, combining it with an empty result container must produce an equivalent result (`javadoc-stream-package#MutableReduction`).

The snippet sums word lengths per first letter with a merge function, tees two collectors, lets the two-argument `toMap` meet a duplicate key, and builds its own collector from a supplier, an accumulator and a combiner.

```java snippet=m11-l01/CollectorMerging.java
import static java.util.stream.Collectors.counting;
import static java.util.stream.Collectors.summingInt;
import static java.util.stream.Collectors.teeing;
import static java.util.stream.Collectors.toMap;

import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.TreeSet;

public class CollectorMerging {
    public static void main(String[] args) {
        List<String> words = List.of("apple", "avocado", "banana", "blueberry", "cherry", "apple");

        Map<Character, Integer> lettersPerInitial = new TreeMap<>(words.stream().collect(
                toMap(w -> w.charAt(0), String::length, Integer::sum)));
        System.out.println(lettersPerInitial);

        String both = words.stream().collect(
                teeing(summingInt(String::length), counting(),
                        (letters, count) -> letters + " letters in " + count + " words"));
        System.out.println(both);

        try {
            words.stream().collect(toMap(w -> w, String::length));
        } catch (IllegalStateException e) {
            System.out.println(e.getMessage());
        }

        TreeSet<Integer> lengths = words.stream().collect(
                TreeSet::new, (set, w) -> set.add(w.length()), TreeSet::addAll);
        System.out.println(lengths);
    }
}
```

The snippet prints `{a=17, b=15, c=6}` for `toMap` with `Integer::sum`, which adds the lengths of equal keys.

It prints `38 letters in 6 words` for `teeing` of `summingInt` and `counting`.

It prints `Duplicate key apple (attempted merging values 5 and 5)` when the two-argument `toMap` meets the second `apple`.

It prints `[5, 6, 7, 9]` for the custom collector, because a `TreeSet` keeps each length once, in order.

## Stream gatherers
<!-- bullets: 11.1.c -->

JEP 485 enhances the Stream API to support custom intermediate operations (`jep-485#Summary`).

Custom intermediate operations let stream pipelines transform data in ways that are not easily achievable with the existing built-in intermediate operations (`jep-485#Summary`).

`Stream.gather` is a stateful intermediate operation that is an extension point (`javadoc-stream#gather(java.util.stream.Gatherer)`).

A `Gatherer` is specified by four functions: initializer, integrator, combiner and finisher (`javadoc-gatherer#interface-gatherer-t-a-r`).

Gatherer operations can be parallelized if a combiner function is supplied (`javadoc-gatherer#interface-gatherer-t-a-r`).

Gatherers are designed to be composed, and two or more can be composed into a single gatherer with `andThen` (`javadoc-gatherer#interface-gatherer-t-a-r`).

A `Gatherer` uses an `Integrator` instead of a `BiConsumer` because it needs an extra input parameter for the `Downstream` object and a boolean result that says whether processing should continue (`jep-485#Gatherers-vs--collectors`).

A `Gatherer` uses a `BiConsumer` for its finisher instead of a `Function` because it needs an extra input parameter for its `Downstream` object and cannot return a result (`jep-485#Gatherers-vs--collectors`).

:::esquema{kind=tabla title="Built-in gatherers in `java.util.stream.Gatherers`"}
| Gatherer | What it does | Source |
|---|---|---|
| `fold` | A stateful many-to-one gatherer that constructs an aggregate incrementally and emits it when no more input elements exist | `jep-485#Built-in-gatherers` |
| `scan` | A stateful one-to-one gatherer that applies a supplied function to the current state and the current element to produce the next element, which it passes downstream | `jep-485#Built-in-gatherers` |
| `windowFixed` | A stateful many-to-many gatherer that groups input elements into lists of a supplied size, emitting the windows downstream when they are full | `jep-485#Built-in-gatherers` |
| `windowSliding` | A stateful many-to-many gatherer that groups input elements into lists of a supplied size; each window after the first drops the first element of its predecessor and appends the next input element | `jep-485#Built-in-gatherers` |
| `mapConcurrent` | A stateful one-to-one gatherer that invokes a supplied function for each input element concurrently, up to a supplied limit | `jep-485#Built-in-gatherers` |
:::

If the stream is empty, `windowFixed` produces no window, and its last window may contain fewer elements than the supplied window size (`javadoc-gatherers#windowFixed(int)`).

`windowFixed` throws `IllegalArgumentException` when `windowSize` is less than 1 (`javadoc-gatherers#windowFixed(int)`).

Each window produced by `windowFixed` is an unmodifiable `List`, and any mutator call throws `UnsupportedOperationException` (`javadoc-gatherers#windowFixed(int)`).

In `windowSliding`, each subsequent window includes all elements of the previous window except the least recent, and adds the next element in the stream (`javadoc-gatherers#windowSliding(int)`).

If the stream is smaller than the window size, `windowSliding` produces one window that holds all elements of the stream (`javadoc-gatherers#windowSliding(int)`).

`fold` performs an ordered, reduction-like transformation for scenarios where no combiner function can be implemented, or for reductions that are intrinsically order-dependent (`javadoc-gatherers#fold(java.util.function.Supplier,java.util.function.BiFunction)`).

If no exceptions are thrown during processing, `fold` produces a single element (`javadoc-gatherers#fold(java.util.function.Supplier,java.util.function.BiFunction)`).

`scan` starts with an initial value from the `Supplier`, and each later value comes from applying the `BiFunction` to the current value and the next input element, after which the result is produced downstream (`javadoc-gatherers#scan(java.util.function.Supplier,java.util.function.BiFunction)`).

The snippet applies the built-in gatherers to small integer streams and tries to add to a window.

```java snippet=m11-l01/GathererSteps.java
import java.util.List;
import java.util.stream.Gatherers;
import java.util.stream.Stream;

public class GathererSteps {
    public static void main(String[] args) {
        System.out.println(Stream.of(1, 2, 3, 4, 5, 6, 7, 8).gather(Gatherers.windowFixed(3)).toList());
        System.out.println(Stream.of(1, 2, 3, 4, 5).gather(Gatherers.windowSliding(3)).toList());
        System.out.println(Stream.of(1, 2, 3, 4).gather(Gatherers.windowSliding(6)).toList());
        System.out.println(Stream.<Integer>empty().gather(Gatherers.windowFixed(3)).toList());
        System.out.println(Stream.of(1, 2, 3, 4, 5).gather(Gatherers.fold(() -> 0, Integer::sum)).toList());
        System.out.println(Stream.of(1, 2, 3, 4, 5).gather(Gatherers.scan(() -> 0, Integer::sum)).toList());
        List<List<Integer>> windows = Stream.of(1, 2, 3).gather(Gatherers.windowFixed(2)).toList();
        try {
            windows.get(0).add(9);
        } catch (UnsupportedOperationException e) {
            System.out.println("windows are unmodifiable");
        }
    }
}
```

The snippet prints `[[1, 2, 3], [4, 5, 6], [7, 8]]` for `windowFixed(3)` over 1 to 8, with a short last window.

It prints `[[1, 2, 3], [2, 3, 4], [3, 4, 5]]` for `windowSliding(3)` over 1 to 5.

It prints `[[1, 2, 3, 4]]` for `windowSliding(6)` over 1 to 4.

It prints `[]` for `windowFixed(3)` over an empty stream.

It prints `[15]` for `fold` with `Integer::sum` over 1 to 5, a single element.

It prints `[1, 3, 6, 10, 15]` for `scan` with `Integer::sum` over 1 to 5, without the initial value `0`.

It prints `windows are unmodifiable` when `add` is called on a window.

## Reading a pipeline
<!-- bullets: 11.1.d -->

A stream pipeline consists of a source, followed by zero or more intermediate operations, and a terminal operation (`javadoc-stream-package#StreamOps`).

Intermediate operations return a new stream and are always lazy (`javadoc-stream-package#StreamOps`).

Traversal of the pipeline source does not begin until the terminal operation of the pipeline is executed (`javadoc-stream-package#StreamOps`).

After the terminal operation is performed, the stream pipeline is considered consumed and can no longer be used (`javadoc-stream-package#StreamOps`).

Stateless operations such as `filter` and `map` retain no state from previously seen elements (`javadoc-stream-package#StreamOps`).

Stateful operations such as `distinct` and `sorted` may incorporate state from previously seen elements (`javadoc-stream-package#StreamOps`).

Stateful operations may need to process the entire input before producing a result (`javadoc-stream-package#StreamOps`).

One cannot produce any results from sorting a stream until one has seen all elements of the stream (`javadoc-stream-package#StreamOps`).

Under parallel computation, some pipelines with stateful intermediate operations may require multiple passes on the data or may need to buffer significant data (`javadoc-stream-package#StreamOps`).

Pipelines that contain only stateless intermediate operations can be processed in a single pass, sequential or parallel, with minimal data buffering (`javadoc-stream-package#StreamOps`).

Having a short-circuiting operation in the pipeline is a necessary, but not sufficient, condition for the processing of an infinite stream to terminate normally in finite time (`javadoc-stream-package#StreamOps`).

Whether a stream has an encounter order depends on the source and the intermediate operations (`javadoc-stream-package#Ordering`).

Streams from a `List` or an array are intrinsically ordered, whereas streams from a `HashSet` are not (`javadoc-stream-package#Ordering`).

`sorted()` may impose an encounter order on an otherwise unordered stream (`javadoc-stream-package#Ordering`).

`forEach()` is a terminal operation that may ignore encounter order (`javadoc-stream-package#Ordering`).

For sequential streams, the presence or absence of an encounter order affects determinism, not performance (`javadoc-stream-package#Ordering`).

Side-effects in the behavioral parameters of stream operations are, in general, discouraged (`javadoc-stream-package#SideEffects`).

With side-effects in behavioral parameters, there is no guarantee that different operations on the same element run in the same thread (`javadoc-stream-package#SideEffects`).

With side-effects in behavioral parameters, there is no guarantee that they are visible to other threads (`javadoc-stream-package#SideEffects`).

With side-effects in behavioral parameters, there is no guarantee that they are always invoked, because a stream implementation may elide operations or entire stages of a pipeline (`javadoc-stream-package#SideEffects`).

Even when a pipeline must produce a result consistent with the encounter order of its source, no guarantees are made about the order in which the mapper function is applied to individual elements (`javadoc-stream-package#SideEffects`).

Adding to an `ArrayList` from `forEach` in a parallel pipeline would cause incorrect results, because `ArrayList` is not thread-safe (`javadoc-stream-package#SideEffects`).

A stateful lambda is one whose result depends on any state that might change during the execution of the stream pipeline (`javadoc-stream-package#Statelessness`).

Stream pipeline results may be nondeterministic or incorrect if the behavioral parameters of the stream operations are stateful (`javadoc-stream-package#Statelessness`).

The stream implementations in the JDK create serial streams unless parallelism is explicitly requested (`javadoc-stream-package#Parallelism`).

Except for operations identified as explicitly nondeterministic, such as `findAny()`, whether a stream executes sequentially or in parallel should not change the result (`javadoc-stream-package#Parallelism`).

An implementation of `count()` may choose not to execute the pipeline if it can compute the count directly from the stream source (`javadoc-stream#count()`).

The snippet traces a pipeline with `peek`, counts a stream that has a `peek`, cuts an infinite stream with `takeWhile`, and reuses a consumed stream.

```java snippet=m11-l01/PipelineTrace.java
import java.util.stream.Stream;

public class PipelineTrace {
    public static void main(String[] args) {
        System.out.println(Stream.of("a", "b", "c", "d")
                .peek(s -> System.out.println("peek " + s))
                .map(String::toUpperCase)
                .filter(s -> s.equals("B"))
                .findFirst());

        long counted = Stream.of(1, 2, 3)
                .peek(n -> System.out.println("counting " + n))
                .count();
        System.out.println(counted);

        System.out.println(Stream.iterate(1, n -> n * 2).takeWhile(n -> n < 100).toList());

        Stream<Integer> used = Stream.of(1, 2);
        used.toList();
        try {
            used.toList();
        } catch (IllegalStateException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

The snippet prints `peek a`, `peek b` and `Optional[B]` for the `findFirst` pipeline, and never reaches `c` or `d`.

It prints `3` for `count()` over `Stream.of(1, 2, 3)` with a `peek`, and no `counting` line, because the count comes from the source.

It prints `[1, 2, 4, 8, 16, 32, 64]` for `takeWhile(n -> n < 100)` over the infinite `Stream.iterate(1, n -> n * 2)`.

It prints `stream has already been operated upon or closed` when a consumed stream is used again.

## Key points

- `flatMap` replaces each element with the contents of a mapped stream; a null mapped stream counts as empty.
- `takeWhile` keeps the longest prefix that matches and `dropWhile` drops it; `filter` tests every element.
- `reduce` needs an identity and an associative accumulator; the identity is the start value and the result for empty input.
- `thenComparing` applies only when the first comparator sees two elements as equal; `nullsFirst` orders null before non-null.
- `groupingBy` reduces each group with a downstream collector, and `partitioningBy` always holds both `false` and `true`.
- `toMap` with a merge function merges values of equal keys; the other forms throw on a duplicate key.
- `teeing` sends every element to two collectors and merges their results.
- A `collect` operation needs a supplier, an accumulator and a combiner.
- A `Gatherer` is a custom intermediate operation with an initializer, an integrator, a combiner and a finisher.
- `windowFixed` may end with a short window, `windowSliding` drops the oldest element per step, `fold` emits one element and `scan` emits every running value.
- Intermediate operations are lazy, and nothing runs before the terminal operation; a consumed stream cannot be reused.
- Stateful operations such as `sorted` may need the entire input, and a short-circuiting operation is necessary but not sufficient to end an infinite stream.
- Behavioral parameters with side-effects may run in any thread and order, or be elided; `count()` may skip the pipeline.
