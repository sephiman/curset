# Graphs

## Representing a graph
<!-- bullets: 2.4.a -->

An adjacency matrix represents a graph with n vertices as an n by n matrix of boolean values (`ods-12-1-adjacencymatrix-repres#SECTION001510000000000000000`).

In an adjacency list representation, the graph is an array of lists (`ods-12-2-adjacencylists-graph-a#SECTION001520000000000000000`).

The list at an index holds all the vertices adjacent to that vertex (`ods-12-2-adjacencylists-graph-a#SECTION001520000000000000000`).

Unless a chapter states otherwise, the time bounds of graph algorithms in Erickson's book assume a standard adjacency list (`erickson-graphs#p13`).

:::esquema{kind=tabla title="Two ways to store a graph"}
| Representation | What the book states | Citation |
| --- | --- | --- |
| Adjacency matrix | Adding, removing and testing an edge take constant time per operation | `ods-12-1-adjacencymatrix-repres#SECTION001510000000000000000` |
| Adjacency matrix | The representation is large | `ods-12-1-adjacencymatrix-repres#SECTION001510000000000000000` |
| Adjacency lists | Reading the out-edges of a vertex returns its list, in constant time | `ods-12-2-adjacencylists-graph-a#SECTION001520000000000000000` |
| Adjacency lists | Finding the in-edges of a vertex scans the adjacency list of every vertex | `ods-12-2-adjacencylists-graph-a#SECTION001520000000000000000` |
:::

## Breadth-first and depth-first search
<!-- bullets: 2.4.a -->

Breadth-first search uses a queue that initially contains only the start vertex (`ods-12-3-graph-traversal#SECTION001531000000000000000`).

Breadth-first search tracks which vertices have already been discovered with an auxiliary boolean array (`ods-12-3-graph-traversal#SECTION001531000000000000000`).

Breadth-first search visits vertices in increasing order of distance from the start vertex (`ods-12-3-graph-traversal#SECTION001531000000000000000`).

Depth-first search is similar to breadth-first search except that it uses a stack instead of a queue (`ods-12-3-graph-traversal#SECTION001532000000000000000`).

Depth-first search can be written either recursively or iteratively (`erickson-graphs#p13`).

A recursive depth-first search fails on many large graphs by causing a stack overflow (`ods-12-3-graph-traversal#SECTION001532000000000000000`).

An alternative implementation replaces the recursion stack with an explicit stack (`ods-12-3-graph-traversal#SECTION001532000000000000000`).

The snippet stores an undirected graph as adjacency lists on vertices 0 to 6, with the edges 0-1, 0-2, 1-3, 2-3, 3-4 and 5-6. It runs a queue-based breadth-first search and a recursive depth-first search from vertex 0.

```java snippet=m02-l04/GraphTraversal.java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;
import java.util.Queue;

public class GraphTraversal {
    static List<List<Integer>> graph(int vertices, int[][] edges) {
        List<List<Integer>> adjacency = new ArrayList<>();
        for (int v = 0; v < vertices; v++) {
            adjacency.add(new ArrayList<>());
        }
        for (int[] edge : edges) {
            adjacency.get(edge[0]).add(edge[1]);
            adjacency.get(edge[1]).add(edge[0]);
        }
        return adjacency;
    }

    static List<Integer> bfs(List<List<Integer>> adjacency, int start) {
        List<Integer> order = new ArrayList<>();
        boolean[] seen = new boolean[adjacency.size()];
        Queue<Integer> queue = new ArrayDeque<>();
        queue.add(start);
        seen[start] = true;
        while (!queue.isEmpty()) {
            int v = queue.remove();
            order.add(v);
            for (int w : adjacency.get(v)) {
                if (!seen[w]) {
                    seen[w] = true;
                    queue.add(w);
                }
            }
        }
        return order;
    }

    static void dfs(List<List<Integer>> adjacency, int v, boolean[] seen, List<Integer> order) {
        seen[v] = true;
        order.add(v);
        for (int w : adjacency.get(v)) {
            if (!seen[w]) {
                dfs(adjacency, w, seen, order);
            }
        }
    }

    public static void main(String[] args) {
        List<List<Integer>> adjacency = graph(7, new int[][] {{0, 1}, {0, 2}, {1, 3}, {2, 3}, {3, 4}, {5, 6}});
        System.out.println("bfs " + bfs(adjacency, 0));

        List<Integer> order = new ArrayList<>();
        dfs(adjacency, 0, new boolean[adjacency.size()], order);
        System.out.println("dfs " + order);

        boolean[] seen = new boolean[adjacency.size()];
        int components = 0;
        for (int v = 0; v < adjacency.size(); v++) {
            if (!seen[v]) {
                dfs(adjacency, v, seen, new ArrayList<>());
                components++;
            }
        }
        System.out.println("components " + components);
    }
}
```

The breadth-first search prints `bfs [0, 1, 2, 3, 4]`.

The depth-first search prints `dfs [0, 1, 3, 2, 4]`.

## Connected components
<!-- bullets: 2.4.a -->

For undirected graphs, the vertices reachable from a vertex s are precisely the vertices in the same component as s (`erickson-graphs#p13`).

The snippet starts a depth-first search from every vertex that has not been seen yet and counts the starts.

The count is printed as `components 2`.

## Cycle detection and topological sort
<!-- bullets: 2.4.a 2.4.b -->

A directed acyclic graph or dag is a directed graph with no directed cycles (`erickson-dfs#p7`).

A depth-first search can maintain the status of each vertex and return false as soon as it discovers an edge to an active vertex (`erickson-dfs#p7`).

This status-based algorithm runs in O(V + E) time (`erickson-dfs#p7`).

Topological order is the same as reversed postorder (`erickson-dfs#p9`).

To process a directed acyclic graph in reverse topological order, it suffices to process each vertex at the end of its recursive depth-first search (`erickson-dfs#p9`).

The snippet marks each vertex as new, active or finished. A directed graph on vertices 0 to 4 has the edges 0 to 1, 0 to 2, 1 to 3, 2 to 3 and 3 to 4. The snippet reverses the postorder of its depth-first search, then adds the edge 4 to 1 and checks for a cycle.

```java snippet=m02-l04/CycleAndTopologicalSort.java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class CycleAndTopologicalSort {
    enum Status { NEW, ACTIVE, FINISHED }

    static boolean hasCycle(List<List<Integer>> adjacency) {
        Status[] status = new Status[adjacency.size()];
        java.util.Arrays.fill(status, Status.NEW);
        for (int v = 0; v < adjacency.size(); v++) {
            if (status[v] == Status.NEW && visitFindsCycle(adjacency, v, status, new ArrayList<>())) {
                return true;
            }
        }
        return false;
    }

    static boolean visitFindsCycle(List<List<Integer>> adjacency, int v, Status[] status, List<Integer> postorder) {
        status[v] = Status.ACTIVE;
        for (int w : adjacency.get(v)) {
            if (status[w] == Status.ACTIVE) {
                return true;
            }
            if (status[w] == Status.NEW && visitFindsCycle(adjacency, w, status, postorder)) {
                return true;
            }
        }
        status[v] = Status.FINISHED;
        postorder.add(v);
        return false;
    }

    static List<Integer> topologicalOrder(List<List<Integer>> adjacency) {
        Status[] status = new Status[adjacency.size()];
        java.util.Arrays.fill(status, Status.NEW);
        List<Integer> postorder = new ArrayList<>();
        for (int v = 0; v < adjacency.size(); v++) {
            if (status[v] == Status.NEW) {
                visitFindsCycle(adjacency, v, status, postorder);
            }
        }
        Collections.reverse(postorder);
        return postorder;
    }

    static List<List<Integer>> directed(int vertices, int[][] edges) {
        List<List<Integer>> adjacency = new ArrayList<>();
        for (int v = 0; v < vertices; v++) {
            adjacency.add(new ArrayList<>());
        }
        for (int[] edge : edges) {
            adjacency.get(edge[0]).add(edge[1]);
        }
        return adjacency;
    }

    public static void main(String[] args) {
        int[][] dag = {{0, 1}, {0, 2}, {1, 3}, {2, 3}, {3, 4}};
        System.out.println("topological " + topologicalOrder(directed(5, dag)));
        System.out.println("dag has cycle " + hasCycle(directed(5, dag)));

        int[][] withBackEdge = {{0, 1}, {0, 2}, {1, 3}, {2, 3}, {3, 4}, {4, 1}};
        System.out.println("with edge 4->1 has cycle " + hasCycle(directed(5, withBackEdge)));
    }
}
```

The reversed postorder is printed as `topological [0, 2, 1, 3, 4]`.

The graph without the extra edge prints `dag has cycle false`.

The graph with the edge 4 to 1 prints `with edge 4->1 has cycle true`.

## Union-find
<!-- bullets: 2.4.b -->

Each set in a disjoint-set data structure has a unique leader element, which identifies the set (`erickson-union-find#p1`).

Find(x) finds the leader of the set containing x (`erickson-union-find#p1`).

Union(A, B) replaces two sets A and B in the collection with their union (`erickson-union-find#p1`).

Kruskal's minimum spanning tree algorithm relies on a disjoint-set data structure to maintain the components of the intermediate spanning forest (`erickson-union-find#p1`).

Once a Find operation has determined the leader of an object x, redirecting the parent pointer of x directly to that leader speeds up future Finds (`erickson-union-find#p4`).

This modification to Find is called path compression (`erickson-union-find#p4`).

The snippet stores each set as a tree of parent pointers. Three unions chain the elements 0, 1, 2 and 3 into one path, and then `find(0)` compresses that path.

```java snippet=m02-l04/UnionFind.java
import java.util.Arrays;

public class UnionFind {
    static int find(int[] parent, int x) {
        if (parent[x] != x) {
            parent[x] = find(parent, parent[x]);
        }
        return parent[x];
    }

    static void union(int[] parent, int a, int b) {
        parent[find(parent, a)] = find(parent, b);
    }

    public static void main(String[] args) {
        int[] parent = {0, 1, 2, 3};
        union(parent, 0, 1);
        union(parent, 1, 2);
        union(parent, 2, 3);
        System.out.println("before " + Arrays.toString(parent));

        find(parent, 0);
        System.out.println("after find(0) " + Arrays.toString(parent));

        long leaders = java.util.stream.IntStream.range(0, parent.length).filter(x -> parent[x] == x).count();
        System.out.println("components " + leaders);
    }
}
```

The parent array before the call is printed as `before [1, 2, 3, 3]`.

After `find(0)` it is printed as `after find(0) [3, 3, 3, 3]`.

The number of leaders is printed as `components 1`.

## Shortest paths
<!-- bullets: 2.4.b -->

A particularly useful application of breadth-first search is computing shortest paths (`ods-12-3-graph-traversal#SECTION001531000000000000000`).

In Dijkstra's algorithm, unlike in breadth-first search, each distance label dist(v) can change multiple times (`erickson-shortest-paths#p15`).

When the graph has no negative-weight edges, Dijkstra's algorithm extracts each vertex from the priority queue at most once (`erickson-shortest-paths#p15`).

When the graph has no negative-weight edges, Dijkstra's algorithm ends with dist(v) equal to the length of the shortest path from the source to every vertex v (`erickson-shortest-paths#p15`).

The snippet settles vertices from a `PriorityQueue` ordered by distance and relaxes the edges of each settled vertex once. The first graph has four vertices and non-negative weights.

```java snippet=m02-l04/Dijkstra.java
import java.util.Arrays;
import java.util.PriorityQueue;

public class Dijkstra {
    static int[] shortestDistances(int[][][] adjacency, int source) {
        int[] distance = new int[adjacency.length];
        Arrays.fill(distance, Integer.MAX_VALUE);
        distance[source] = 0;
        boolean[] settled = new boolean[adjacency.length];
        PriorityQueue<int[]> queue = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        queue.add(new int[] {0, source});
        while (!queue.isEmpty()) {
            int v = queue.remove()[1];
            if (settled[v]) {
                continue;
            }
            settled[v] = true;
            for (int[] edge : adjacency[v]) {
                int w = edge[0];
                if (!settled[w] && distance[v] + edge[1] < distance[w]) {
                    distance[w] = distance[v] + edge[1];
                    queue.add(new int[] {distance[w], w});
                }
            }
        }
        return distance;
    }

    public static void main(String[] args) {
        int[][][] nonNegative = {
            {{1, 4}, {2, 1}},
            {{3, 1}},
            {{1, 2}, {3, 5}},
            {}
        };
        System.out.println("distances " + Arrays.toString(shortestDistances(nonNegative, 0)));

        int[][][] negativeEdge = {
            {{1, 2}, {2, 3}},
            {},
            {{1, -2}}
        };
        System.out.println("with a negative edge " + Arrays.toString(shortestDistances(negativeEdge, 0)));
    }
}
```

It prints `distances [0, 3, 1, 4]` for the first graph.

The second graph breaks the precondition on purpose: it has an edge of weight -2 from vertex 2 to vertex 1. The path through vertex 2 costs 3 + (-2) = 1.

The snippet still prints `with a negative edge [0, 2, 3]`, so it reports 2 for vertex 1.

## Grids as implicit graphs
<!-- bullets: 2.4.c -->

Any graph algorithm can be applied to a configuration graph as though it were a standard adjacency list, provided all possible moves from a configuration can be enumerated in constant time each (`erickson-graphs#p13`).

The dependency graph of the edit distance recurrence is an m by n grid of vertices (`erickson-graphs#p7`).

The snippet treats each open cell of a 3 by 4 grid as a vertex and each move up, down, left or right as an edge. The cell `S` is the start, `E` is the goal and `#` is a wall. No adjacency list is built.

```text
S.#.
.##.
...E
```

```java snippet=m02-l04/GridSearch.java
import java.util.ArrayDeque;
import java.util.Queue;

public class GridSearch {
    static final int[][] MOVES = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public static void main(String[] args) {
        String[] grid = {
            "S.#.",
            ".##.",
            "...E"
        };
        int rows = grid.length;
        int columns = grid[0].length();
        int[][] steps = new int[rows][columns];
        for (int[] row : steps) {
            java.util.Arrays.fill(row, -1);
        }
        Queue<int[]> queue = new ArrayDeque<>();
        queue.add(new int[] {0, 0});
        steps[0][0] = 0;
        int reachable = 0;
        while (!queue.isEmpty()) {
            int[] cell = queue.remove();
            reachable++;
            for (int[] move : MOVES) {
                int r = cell[0] + move[0];
                int c = cell[1] + move[1];
                boolean inside = r >= 0 && r < rows && c >= 0 && c < columns;
                if (inside && grid[r].charAt(c) != '#' && steps[r][c] < 0) {
                    steps[r][c] = steps[cell[0]][cell[1]] + 1;
                    queue.add(new int[] {r, c});
                }
            }
        }
        System.out.println("steps to E " + steps[2][3]);
        System.out.println("reachable cells " + reachable);
    }
}
```

The breadth-first search prints `steps to E 5`.

It prints `reachable cells 9`.

## Key points

- An adjacency matrix is an n by n matrix of booleans, and an adjacency list representation is an array of lists.
- Breadth-first search uses a queue and visits vertices in increasing order of distance from the start vertex.
- Depth-first search is breadth-first search with a stack instead of a queue; a recursive version can overflow the stack on large graphs.
- For undirected graphs, the vertices reachable from s are the vertices in the same component as s.
- Topological order is reversed postorder, and a depth-first search that finds an edge to an active vertex has found a cycle.
- Path compression redirects the parent pointer of x directly to the leader after a Find.
- Dijkstra's algorithm gives the shortest path lengths when the graph has no negative-weight edges, and the snippet shows a wrong result with one.
- A grid can be searched as an implicit graph when all moves from a cell can be enumerated in constant time each.
