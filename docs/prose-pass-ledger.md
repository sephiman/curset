## How to read this ledger

- One section per lesson, in course order, with **status** `done` / `in progress` / `not started`. A
  lesson is `done` only after both locales are rewritten, reviewed and regenerated, with the checks below
  green.
- "Before" is `HEAD` (`eecbf11`), which predates the pilot. The pilot lessons (m08-l1, m27-l1) are covered by
  `docs/prose-pilot-ledger.md`.
- Before/after tables are generated by aligning the sentences of `HEAD` with the current file. A row is a
  passage that changed: one sentence, or a sentence and the pieces it was split into.
- **Checks run after every lesson** (all must hold, or the lesson is not `done`):
  every number token in the lesson is the same multiset as before; «nunca / siempre / debe…» and
  «never / always / must» counts are unchanged; `::` directives, `:::note` blocks and headings are
  byte-identical (unless a coined-term rename was decided); guard phrases are present; bold is unchanged.
  Then the regeneration: `glossary-links` and `lesson-refs` regenerated, with every (lesson, term) and
  (lesson, target) pair compared against `HEAD`; `export_bundle.py` with text diff 0, block inventory
  and exercise refs OK; `export_generation_goldens.py` with **zero diff** against the session baseline.
- **lesson-refs:** the report quotes the text around each reference, so a rewritten sentence next to
  "m26" changes the file. I treat it as unchanged when every (lesson, target, kind, key) row is the same
  as at `HEAD` and only the quoted context differs. A row added or lost stops the pass.
- **Exercises are not touched during the lesson pass.** Coined terms found in exercise YAML are logged in
  "Exercise terms to fix" and fixed in the final, separate step at the end of this ledger.
