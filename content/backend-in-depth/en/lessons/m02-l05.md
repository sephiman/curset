# Algorithm design techniques

## Recursion
<!-- bullets: 2.5.a -->

A recursive method needs an elementary base case, because there must be no infinite sequence of reductions to simpler and simpler instances (`erickson-recursion#p3`).

Without a base case, the recursive algorithm will loop forever (`erickson-recursion#p3`).

The most common way to satisfy this condition is to reduce to one or more smaller instances of the same problem (`erickson-recursion#p3`).

## Backtracking: subsets, permutations and pruning
<!-- bullets: 2.5.a -->

Backtracking algorithms are commonly used to make a sequence of decisions, with the goal of building a recursively defined structure satisfying certain constraints (`erickson-backtracking#p9`).

In each recursive call to a backtracking algorithm, exactly one decision is made, and the choice must be consistent with all previous decisions (`erickson-backtracking#p9`).

For each row of the n queens problem, the algorithm decides where to place the queen (`erickson-backtracking#p9`).

In the subset sum problem, the algorithm decides for each input element whether to include it in the output sequence or not (`erickson-backtracking#p9`).

A backtracking search for complete solutions is equivalent to a depth-first search of the recursion tree (`erickson-backtracking#p3`).

For the sake of efficiency, the summary of past decisions should be as small as possible (`erickson-backtracking#p9`).

The first snippet builds all subsets of 1, 2, 3 by choosing, recursing and undoing the choice. It builds all permutations by marking each element as used while it is in the partial result.

```java snippet=m02-l05/SubsetsAndPermutations.java
import java.util.ArrayList;
import java.util.List;

public class SubsetsAndPermutations {
    static void subsets(int[] items, int from, List<Integer> chosen, List<List<Integer>> out) {
        out.add(new ArrayList<>(chosen));
        for (int i = from; i < items.length; i++) {
            chosen.add(items[i]);
            subsets(items, i + 1, chosen, out);
            chosen.remove(chosen.size() - 1);
        }
    }

    static void permutations(int[] items, boolean[] used, List<Integer> chosen, List<List<Integer>> out) {
        if (chosen.size() == items.length) {
            out.add(new ArrayList<>(chosen));
            return;
        }
        for (int i = 0; i < items.length; i++) {
            if (!used[i]) {
                used[i] = true;
                chosen.add(items[i]);
                permutations(items, used, chosen, out);
                chosen.remove(chosen.size() - 1);
                used[i] = false;
            }
        }
    }

    public static void main(String[] args) {
        int[] items = {1, 2, 3};
        List<List<Integer>> subsets = new ArrayList<>();
        subsets(items, 0, new ArrayList<>(), subsets);
        System.out.println("subsets " + subsets);

        List<List<Integer>> permutations = new ArrayList<>();
        permutations(items, new boolean[items.length], new ArrayList<>(), permutations);
        System.out.println("permutations " + permutations.size() + " first " + permutations.get(0)
                + " last " + permutations.get(permutations.size() - 1));
    }
}
```

The subsets are printed as `subsets [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]`.

The permutations are printed as `permutations 6 first [1, 2, 3] last [3, 2, 1]`.

In subset sum, if the target T is negative or the set X is empty, no subset of X sums to T (`erickson-backtracking#p7`).

Leaves of the recursion tree of the n queens algorithm are partial solutions that cannot be extended, either because there is already a queen on every row, or because every position in the next empty row is attacked by an existing queen (`erickson-backtracking#p3`).

The second snippet searches the subsets of 1 to 5 that sum to 5, once with the test that stops when the remaining target is negative and once without it. It counts the recursive calls.

```java snippet=m02-l05/SubsetSumPruning.java
import java.util.ArrayList;
import java.util.List;

public class SubsetSumPruning {
    static int calls;

    static void search(int[] items, int index, int remaining, boolean prune, List<Integer> chosen,
            List<List<Integer>> found) {
        calls++;
        if (remaining == 0) {
            found.add(new ArrayList<>(chosen));
            return;
        }
        if (index == items.length || (prune && remaining < 0)) {
            return;
        }
        chosen.add(items[index]);
        search(items, index + 1, remaining - items[index], prune, chosen, found);
        chosen.remove(chosen.size() - 1);
        search(items, index + 1, remaining, prune, chosen, found);
    }

    public static void main(String[] args) {
        int[] items = {1, 2, 3, 4, 5};

        calls = 0;
        List<List<Integer>> found = new ArrayList<>();
        search(items, 0, 5, true, new ArrayList<>(), found);
        System.out.println("subsets that sum to 5 " + found);
        System.out.println("calls with pruning " + calls);

        calls = 0;
        search(items, 0, 5, false, new ArrayList<>(), new ArrayList<>());
        System.out.println("calls without pruning " + calls);
    }
}
```

It prints `subsets that sum to 5 [[1, 4], [2, 3], [5]]`.

The pruned search makes `calls with pruning 41` and the unpruned search makes `calls without pruning 55`.

## Dynamic programming: state, memoisation and tabulation
<!-- bullets: 2.5.b -->

The naive recursive algorithm for the Fibonacci numbers is horribly slow (`erickson-dynamic-programming#p3`).

The running time of the naive recursive Fibonacci algorithm is exponential in n (`erickson-dynamic-programming#p3`).

The reason is that it computes the same Fibonacci numbers over and over and over (`erickson-dynamic-programming#p3`).

Memoisation writes down the results of recursive calls and looks them up again if they are needed later (`erickson-dynamic-programming#p3`).

In a nutshell, dynamic programming is recursion without repetition (`erickson-dynamic-programming#p9`).

Dynamic programming algorithms store the solutions of intermediate subproblems, often but not always in some kind of array or table (`erickson-dynamic-programming#p9`).

The snippet counts the calls of a naive recursive Fibonacci and of a version that stores each result in a map.

```java snippet=m02-l05/FibonacciMemoisation.java
import java.util.HashMap;
import java.util.Map;

public class FibonacciMemoisation {
    static long naiveCalls;
    static long memoisedCalls;

    static long naive(int n) {
        naiveCalls++;
        return n < 2 ? n : naive(n - 1) + naive(n - 2);
    }

    static long memoised(int n, Map<Integer, Long> memo) {
        memoisedCalls++;
        if (n < 2) {
            return n;
        }
        Long known = memo.get(n);
        if (known != null) {
            return known;
        }
        long value = memoised(n - 1, memo) + memoised(n - 2, memo);
        memo.put(n, value);
        return value;
    }

    public static void main(String[] args) {
        System.out.println("fib(20) " + naive(20));
        System.out.println("naive calls " + naiveCalls);
        memoised(20, new HashMap<>());
        System.out.println("memoised calls " + memoisedCalls);
    }
}
```

For n = 20 it prints `fib(20) 6765`.

The naive version makes `naive calls 21891` and the memoised version makes `memoised calls 39`.

In text segmentation, each subproblem Splittable(i) depends only on subproblems Splittable(j) with j > i, so the memoised algorithm fills its array in decreasing index order (`erickson-dynamic-programming#p9`).

A memoisation data structure has to store the solution to every subproblem identified, and is usually but not always a multidimensional array (`erickson-dynamic-programming#p11`).

A good evaluation order puts each subproblem after the subproblems it depends on (`erickson-dynamic-programming#p11`).

The number of distinct subproblems determines the space complexity of a memoised algorithm (`erickson-dynamic-programming#p11`).

## Dynamic programming: common patterns
<!-- bullets: 2.5.b -->

Both backtracking algorithms for the longest increasing subsequence can be sped up significantly via dynamic programming (`erickson-dynamic-programming#p13`).

Each `LISbigger` subproblem is identified by two indices, so there are only `O(n^2)` distinct recursive subproblems (`erickson-dynamic-programming#p13`).

The array-based dynamic programming algorithm for the longest increasing subsequence runs in `O(n^2)` time and uses `O(n)` space (`erickson-dynamic-programming#p15`).

The edit distance between two strings is the minimum number of letter insertions, letter deletions and letter substitutions required to transform one string into the other (`erickson-dynamic-programming#p15`).

The edit distance between FOOD and MONEY is exactly four (`erickson-dynamic-programming#p15`).

The snippet fills tables for a 0/1 knapsack with weights 1, 3, 4, 5, values 1, 4, 5, 7 and capacity 7, for the longest increasing subsequence of 3, 1, 4, 1, 5, 9, 2, 6, for the edit distance, and for the paths through a 3 by 3 grid that move only right or down.

```java snippet=m02-l05/TabulatedPatterns.java
public class TabulatedPatterns {
    static int knapsack(int[] weights, int[] values, int capacity) {
        int[] best = new int[capacity + 1];
        for (int item = 0; item < weights.length; item++) {
            for (int c = capacity; c >= weights[item]; c--) {
                best[c] = Math.max(best[c], best[c - weights[item]] + values[item]);
            }
        }
        return best[capacity];
    }

    static int longestIncreasingSubsequence(int[] a) {
        int[] lisFirst = new int[a.length];
        int best = 0;
        for (int i = a.length - 1; i >= 0; i--) {
            lisFirst[i] = 1;
            for (int j = i + 1; j < a.length; j++) {
                if (a[j] > a[i]) {
                    lisFirst[i] = Math.max(lisFirst[i], 1 + lisFirst[j]);
                }
            }
            best = Math.max(best, lisFirst[i]);
        }
        return best;
    }

    static int editDistance(String from, String to) {
        int[][] edit = new int[from.length() + 1][to.length() + 1];
        for (int i = 0; i <= from.length(); i++) {
            edit[i][0] = i;
        }
        for (int j = 0; j <= to.length(); j++) {
            edit[0][j] = j;
        }
        for (int i = 1; i <= from.length(); i++) {
            for (int j = 1; j <= to.length(); j++) {
                int substitution = edit[i - 1][j - 1] + (from.charAt(i - 1) == to.charAt(j - 1) ? 0 : 1);
                edit[i][j] = Math.min(substitution, Math.min(edit[i - 1][j] + 1, edit[i][j - 1] + 1));
            }
        }
        return edit[from.length()][to.length()];
    }

    static long gridPaths(int rows, int columns) {
        long[][] paths = new long[rows][columns];
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < columns; c++) {
                paths[r][c] = r == 0 || c == 0 ? 1 : paths[r - 1][c] + paths[r][c - 1];
            }
        }
        return paths[rows - 1][columns - 1];
    }

    public static void main(String[] args) {
        System.out.println("knapsack " + knapsack(new int[] {1, 3, 4, 5}, new int[] {1, 4, 5, 7}, 7));
        System.out.println("longest increasing subsequence " + longestIncreasingSubsequence(new int[] {3, 1, 4, 1, 5, 9, 2, 6}));
        System.out.println("edit distance " + editDistance("FOOD", "MONEY"));
        System.out.println("grid paths " + gridPaths(3, 3));
    }
}
```

The knapsack table gives `knapsack 9`.

The subsequence table gives `longest increasing subsequence 4`.

The edit distance table gives `edit distance 4` for `FOOD` and `MONEY`.

The grid table gives `grid paths 6`.

## Greedy algorithms
<!-- bullets: 2.5.c -->

A greedy algorithm constructs a solution through a series of decisions, like a backtracking algorithm, but makes those decisions directly, without solving any recursive subproblems (`erickson-dynamic-programming#p11`).

Optimization problems that can be solved correctly by a greedy algorithm are quite rare (`erickson-dynamic-programming#p11`).

A greedy proof argues that the optimal choice can be exchanged for the greedy choice without making the solution worse (`erickson-greedy#p7`).

This argument implies by induction that some optimal solution contains the entire greedy solution, and therefore equals the greedy solution (`erickson-greedy#p7`).

If two adjacent files are out of order, swapping them improves the total cost (`erickson-greedy#p3`).

An edge is safe if it is the minimum-weight edge with exactly one endpoint in some component of the intermediate spanning forest F (`erickson-mst#p3`).

The snippet schedules four classes (1 to 10), (2 to 3), (4 to 5) and (6 to 7), once by earliest start and once by earliest finish. It also fills the knapsack of the previous section greedily, by value per weight.

```java snippet=m02-l05/GreedyChoices.java
import java.util.Arrays;
import java.util.Comparator;

public class GreedyChoices {
    static int scheduled(int[][] classes, Comparator<int[]> order) {
        int[][] sorted = classes.clone();
        Arrays.sort(sorted, order);
        int count = 0;
        int lastFinish = Integer.MIN_VALUE;
        for (int[] c : sorted) {
            if (c[0] >= lastFinish) {
                count++;
                lastFinish = c[1];
            }
        }
        return count;
    }

    static int greedyKnapsack(int[] weights, int[] values, int capacity) {
        Integer[] byRatio = new Integer[weights.length];
        for (int i = 0; i < byRatio.length; i++) {
            byRatio[i] = i;
        }
        Arrays.sort(byRatio, Comparator.comparingDouble((Integer i) -> (double) values[i] / weights[i]).reversed());
        int total = 0;
        for (int i : byRatio) {
            if (weights[i] <= capacity) {
                capacity -= weights[i];
                total += values[i];
            }
        }
        return total;
    }

    public static void main(String[] args) {
        int[][] classes = {{1, 10}, {2, 3}, {4, 5}, {6, 7}};
        System.out.println("earliest start " + scheduled(classes, Comparator.comparingInt(c -> c[0])));
        System.out.println("earliest finish " + scheduled(classes, Comparator.comparingInt(c -> c[1])));
        System.out.println("greedy knapsack " + greedyKnapsack(new int[] {1, 3, 4, 5}, new int[] {1, 4, 5, 7}, 7));
    }
}
```

Choosing by earliest start prints `earliest start 1`.

Choosing by earliest finish prints `earliest finish 3`.

The greedy knapsack prints `greedy knapsack 8`, while the table above found 9.

## Basic bit manipulation
<!-- bullets: 2.5.d -->

`Integer.bitCount` returns the number of one-bits in the two's complement binary representation of an int value (`javadoc-integer#bitCount(int)`).

`Integer.highestOneBit` returns an int value with at most a single one-bit, in the position of the highest-order one-bit of its argument (`javadoc-integer#highestOneBit(int)`).

`Integer.numberOfTrailingZeros` returns 32 if its argument is zero (`javadoc-integer#numberOfTrailingZeros(int)`).

The first snippet applies the three methods and tests for a power of two with `n & (n - 1)`.

```java snippet=m02-l05/BitOperations.java
public class BitOperations {
    public static void main(String[] args) {
        System.out.println("ones in 11: " + Integer.bitCount(11));
        System.out.println("highest one-bit of 100: " + Integer.highestOneBit(100));
        System.out.println("trailing zeros of 40: " + Integer.numberOfTrailingZeros(40));
        System.out.println("64 is a power of two: " + ((64 & (64 - 1)) == 0));
        System.out.println("48 is a power of two: " + ((48 & (48 - 1)) == 0));
    }
}
```

The count of one-bits in 11 is printed as `ones in 11: 3`, because 11 is 1011 in binary.

The highest one-bit of 100 is printed as `highest one-bit of 100: 64`.

The trailing zeros of 40 are printed as `trailing zeros of 40: 3`, because 40 is 101000 in binary.

The power-of-two tests print `64 is a power of two: true` and `48 is a power of two: false`.

`Math.floorMod` returns a result with the same sign as the divisor y, or zero (`javadoc-math#floorMod(int,int)`).

`floorMod(-4, +3)` is +2, while `-4 % +3` is -1 (`javadoc-math#floorMod(int,int)`).

A `BitSet` implements a vector of bits that grows as needed (`javadoc-bitset#class-bitset`).

By default, all bits in a `BitSet` initially have the value false (`javadoc-bitset#class-bitset`).

A `BitSet` is not safe for multithreaded use without external synchronization (`javadoc-bitset#class-bitset`).

The second snippet compares `floorMod` with `%` and sets bits 1, 3 and 5 of a `BitSet`.

```java snippet=m02-l05/FloorModAndBitSet.java
import java.util.BitSet;

public class FloorModAndBitSet {
    public static void main(String[] args) {
        System.out.println("floor modulus of -4 and 3: " + Math.floorMod(-4, 3));
        System.out.println("remainder of -4 and 3: " + (-4 % 3));

        BitSet seen = new BitSet();
        seen.set(1);
        seen.set(3);
        seen.set(5);
        System.out.println("bit set length " + seen.length() + ", set bits " + seen.cardinality());
    }
}
```

It prints `floor modulus of -4 and 3: 2` and `remainder of -4 and 3: -1`.

The `BitSet` prints `bit set length 6, set bits 3`.

## Key points

- A recursive method needs a base case, and the recursive reductions must lead to it.
- Backtracking makes one decision per recursive call, consistent with all previous decisions, and a search for complete solutions is a depth-first search of the recursion tree.
- Stopping a branch when the remaining target is negative cut the calls for the subsets of 1 to 5 from 55 to 41.
- Dynamic programming is recursion without repetition: it stores the solutions of intermediate subproblems.
- The naive Fibonacci recursion made 21891 calls for n = 20 and the memoised version made 39.
- The array-based dynamic programming algorithm for the longest increasing subsequence runs in `O(n^2)` time and uses `O(n)` space.
- Greedy algorithms make decisions directly, and problems they solve correctly are quite rare; the exchange argument is the proof technique.
- Greedy by value per weight gave 8 on the knapsack where the table gave 9, and earliest start scheduled 1 class where earliest finish scheduled 3.
- `Integer.bitCount` counts the one-bits of an int in its two's complement representation, `highestOneBit` returns a value with at most a single one-bit, and `numberOfTrailingZeros` returns 32 for zero.
- `Math.floorMod` has the sign of the divisor, so `floorMod(-4, 3)` is 2 while `-4 % 3` is -1.
