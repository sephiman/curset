# GoF patterns in modern backend code

## Creational patterns
<!-- bullets: 1.2.a -->

The JDK and Spring create some objects without a direct constructor call. `Executors` is a class of static factory methods for executors. `HttpClient` and `HttpRequest` are created through builders, which collect the settings first and return the object from `build`. The creation methods refuse invalid arguments before anything is returned.

:::judgement{source="Gamma, Helm, Johnson and Vlissides, Design Patterns, 1st edition (1994); Joshua Bloch, Effective Java, 3rd edition (2017)"}
According to the course's registered chapter lists, Design Patterns covers creational patterns in chapter 3, "Creational Patterns", and Effective Java covers creating and destroying objects in chapter 2, "Creating and Destroying Objects".
:::

`Executors` consists of factory and utility methods for `Executor`, `ExecutorService`, `ScheduledExecutorService`, `ThreadFactory` and `Callable` classes (`javadoc-executors#class-executors`).

`Executors.newFixedThreadPool(int)` creates a thread pool that reuses a fixed number of threads operating off a shared unbounded queue, and it returns the pool as an `ExecutorService` (`javadoc-executors#newFixedThreadPool(int)`).

It throws `IllegalArgumentException` if `nThreads <= 0` (`javadoc-executors#newFixedThreadPool(int)`).

The overload with a `ThreadFactory` uses the provided factory to create new threads when needed (`javadoc-executors#newFixedThreadPool(int,java.util.concurrent.ThreadFactory)`).

The `List.of` and `List.copyOf` static factory methods provide a convenient way to create unmodifiable lists (`javadoc-list#unmodifiable`).

An `HttpClient` is created through a builder, and the `newBuilder` method returns a builder that creates instances of the default `HttpClient` implementation (`javadoc-java-net-http-httpclient#class-httpclient`).

The builder can be used to configure per-client state, such as the preferred protocol version, whether to follow redirects, a proxy and an authenticator (`javadoc-java-net-http-httpclient#class-httpclient`).

`HttpClient.newHttpClient()` returns a new `HttpClient` with default settings and is equivalent to `newBuilder().build()` (`javadoc-java-net-http-httpclient#newHttpClient()`).

The default settings include a preference of HTTP/2 and a redirection policy of `NEVER` (`javadoc-java-net-http-httpclient#newHttpClient()`).

An `HttpRequest` instance is built through an `HttpRequest` builder, which is obtained from one of the `newBuilder` methods (`javadoc-java-net-http-httprequest#class-httprequest`).

Once all required parameters have been set in the builder, `build` will return the `HttpRequest` (`javadoc-java-net-http-httprequest#class-httprequest`).

Builders can be copied and modified many times in order to build multiple related requests that differ in some parameters (`javadoc-java-net-http-httprequest#class-httprequest`).

`HttpRequest.newBuilder(URI)` throws `IllegalArgumentException` if the URI scheme is not supported (`javadoc-java-net-http-httprequest#newBuilder(java.net.URI)`).

`RestClient` has static `create` shortcut methods and also exposes a `builder()` with further options, such as selecting the HTTP library to use (`spring-fw-integration-rest-clients#_create_a_restclient`).

```java snippet=m01-l02/HttpBuilders.java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.time.Duration;
import java.util.concurrent.Executors;

public class HttpBuilders {
    public static void main(String[] args) {
        HttpRequest request = HttpRequest.newBuilder(URI.create("https://example.com/orders"))
                .header("Accept", "application/json")
                .timeout(Duration.ofSeconds(5))
                .GET()
                .build();
        System.out.println(request.method() + " " + request.uri().getPath());
        System.out.println(request.headers().firstValue("Accept").orElse("none"));
        System.out.println(request.timeout().orElseThrow());
        try (HttpClient client = HttpClient.newHttpClient()) {
            System.out.println(client.followRedirects());
            System.out.println(client.version() == HttpClient.Version.HTTP_2);
        }
        try {
            HttpRequest.newBuilder(URI.create("ftp://example.com/file"));
        } catch (IllegalArgumentException e) {
            System.out.println("unsupported scheme");
        }
        try {
            Executors.newFixedThreadPool(0);
        } catch (IllegalArgumentException e) {
            System.out.println("zero threads refused");
        }
    }
}
```

The built request prints `GET /orders`, then the `Accept` header `application/json` and the timeout `PT5S`.

A client made by `newHttpClient()` prints `NEVER` for its redirect policy and `true` for the comparison of its version with `HTTP_2`.

Two refusals follow: `unsupported scheme` for the `ftp` URI and `zero threads refused` for a pool of zero threads.

The snippet builds an `Invoice` through a builder whose `build` method checks the required fields before it constructs the object.

```java snippet=m01-l02/BuilderInvariants.java
public class BuilderInvariants {
    static final class Invoice {
        private final String number;
        private final long cents;

        private Invoice(Builder builder) {
            this.number = builder.number;
            this.cents = builder.cents;
        }

        static Builder builder() {
            return new Builder();
        }

        @Override
        public String toString() {
            return "Invoice " + number + " " + cents;
        }

        static final class Builder {
            private String number;
            private long cents = -1;

            Builder number(String number) {
                this.number = number;
                return this;
            }

            Builder cents(long cents) {
                this.cents = cents;
                return this;
            }

            Invoice build() {
                if (number == null || number.isBlank()) {
                    throw new IllegalStateException("number is required");
                }
                if (cents < 0) {
                    throw new IllegalStateException("cents must not be negative");
                }
                return new Invoice(this);
            }
        }
    }

    public static void main(String[] args) {
        System.out.println(Invoice.builder().number("F-1").cents(1200).build());
        try {
            Invoice.builder().number("F-2").build();
        } catch (IllegalStateException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

The snippet prints `Invoice F-1 1200` for the complete builder.

It prints `cents must not be negative` for the builder that never set `cents`, because `build` throws an `IllegalStateException` before any `Invoice` exists.

## Wrappers around collections and HTTP clients
<!-- bullets: 1.2.b -->

The JDK wraps collections and tasks: `Collections.synchronizedList` returns a thread-safe list backed by a list, and `Collections.checkedList` returns a view that refuses elements of the wrong type. `Collections.enumeration` offers a collection to legacy APIs, and `Executors.callable` makes a `Callable` out of a `Runnable`. Spring adapts several HTTP client libraries to one interface, and a decorator can intercept the invocations of the client.

:::judgement{source="Gamma, Helm, Johnson and Vlissides, Design Patterns, 1st edition (1994)"}
According to the course's registered chapter list, Design Patterns covers structural patterns in chapter 4, "Structural Patterns".
:::

`Collections.synchronizedList` returns a synchronized (thread-safe) list backed by the specified list (`javadoc-collections#synchronizedList(java.util.List)`).

To guarantee serial access, all access to the backing list must be accomplished through the returned list (`javadoc-collections#synchronizedList(java.util.List)`).

`Collections.checkedList` returns a dynamically typesafe view of the specified list, and any attempt to insert an element of the wrong type results in an immediate `ClassCastException` (`javadoc-collections#checkedList(java.util.List,java.lang.Class)`).

`Collections.enumeration` returns an enumeration over the specified collection, which provides interoperability with legacy APIs that require an enumeration as input (`javadoc-collections#enumeration(java.util.Collection)`).

`Executors` has methods that create and return a `Callable` out of other closure-like forms, so they can be used in execution methods requiring `Callable` (`javadoc-executors#class-executors`).

`Executors.callable(Runnable)` returns a `Callable` object that, when called, runs the given task and returns `null` (`javadoc-executors#callable(java.lang.Runnable)`).

```java snippet=m01-l02/Wrappers.java
import java.util.ArrayList;
import java.util.Collections;
import java.util.Enumeration;
import java.util.List;
import java.util.concurrent.Callable;
import java.util.concurrent.Executors;

public class Wrappers {
    @SuppressWarnings({"unchecked", "rawtypes"})
    public static void main(String[] args) throws Exception {
        List<String> backing = new ArrayList<>();
        List<String> synced = Collections.synchronizedList(backing);
        synced.add("a");
        System.out.println(backing);
        List<Integer> checked = Collections.checkedList(new ArrayList<>(), Integer.class);
        try {
            ((List) checked).add("text");
        } catch (ClassCastException e) {
            System.out.println("checked list refused a String");
        }
        Enumeration<String> legacy = Collections.enumeration(List.of("x", "y"));
        System.out.println(Collections.list(legacy));
        Callable<Object> task = Executors.callable(() -> System.out.println("ran"));
        System.out.println(task.call());
    }
}
```

The backing list prints `[a]` after the element was added through the synchronized list, and the checked list prints `checked list refused a String` for a `String` added to a list of `Integer`.

The enumeration read back as a list prints `[x, y]`. The callable prints `ran` when called and then returns `null`, which the snippet prints as `null`.

`RestClient` is a synchronous HTTP client that provides a fluent API to perform requests (`spring-fw-integration-rest-clients#rest-restclient`).

It serves as an abstraction over HTTP libraries, and handles conversion of HTTP request and response content to and from higher level Java objects (`spring-fw-integration-rest-clients#rest-restclient`).

To execute the HTTP request, `RestClient` uses a client HTTP library, and these libraries are adapted via the `ClientRequestFactory` interface (`spring-fw-integration-rest-clients#rest-request-factories`).

Implementations are available for Java's `HttpClient`, the Apache HTTP Components `HttpClient`, Jetty's `HttpClient` and Reactor Netty's `HttpClient`, and `SimpleClientHttpRequestFactory` is a simple default (`spring-fw-integration-rest-clients#rest-request-factories`).

If no request factory is specified when the `RestClient` was built, it uses the Apache or Jetty `HttpClient` if they are available on the classpath, otherwise Java's `HttpClient` if the `java.net.http` module is loaded, and finally the simple default (`spring-fw-integration-rest-clients#rest-request-factories`).

`HttpExchangeAdapter` and `ReactorHttpExchangeAdapter` are contracts that decouple HTTP Interface client infrastructure from the details of invoking the underlying client, and there are adapter implementations for `RestClient`, `WebClient` and `RestTemplate` (`spring-fw-integration-rest-clients#rest-http-service-client-adapter-decorator`).

Client invocations can be intercepted through a decorator configurable in the `HttpServiceProxyFactory.Builder` (`spring-fw-integration-rest-clients#rest-http-service-client-adapter-decorator`).

Built-in decorators can suppress 404 exceptions and return a `ResponseEntity` with `NOT_FOUND` and a null body (`spring-fw-integration-rest-clients#rest-http-service-client-adapter-decorator`).

A facade or service implementation that typically covers more than one repository can define the transactional boundaries for non-CRUD operations (`spring-data-jpa-transactions#page-title`).

## Proxies for clients, caches and transactions
<!-- bullets: 1.2.b -->

A JDK proxy is a class built at runtime for a list of interfaces, and each call on a proxy instance goes to an invocation handler. Spring picks a JDK proxy or a generated subclass for the targets it advises, and it puts proxies in front of cached methods, transactional methods and HTTP service interfaces.

`Proxy` provides static methods for creating objects that act like instances of interfaces but allow for customized method invocation (`javadoc-proxy#class-proxy`).

A proxy class is a class created at runtime that implements a specified list of interfaces, known as proxy interfaces (`javadoc-proxy#class-proxy`).

A proxy instance is an instance of a proxy class (`javadoc-proxy#class-proxy`).

Each proxy instance has an associated invocation handler object, which implements the interface `InvocationHandler` (`javadoc-proxy#class-proxy`).

A method invocation on a proxy instance through one of its proxy interfaces is dispatched to the `invoke` method of the instance's invocation handler (`javadoc-proxy#class-proxy`).

The `invoke` method receives the proxy instance, a `java.lang.reflect.Method` object identifying the method that was invoked, and an array of type `Object` containing the arguments (`javadoc-proxy#class-proxy`).

A proxy class is final and non-abstract (`javadoc-proxy#class-proxy`).

A proxy class extends `java.lang.reflect.Proxy` (`javadoc-proxy#class-proxy`).

A proxy class implements exactly the interfaces specified at its creation, in the same order (`javadoc-proxy#class-proxy`).

For a proxy instance `proxy` and an interface `Foo` implemented by its proxy class, `proxy instanceof Foo` returns true and the cast `(Foo) proxy` succeeds (`javadoc-proxy#class-proxy`).

An invocation of the `hashCode`, `equals` or `toString` methods declared in `java.lang.Object` on a proxy instance is dispatched to the handler's `invoke` method in the same manner as an interface method invocation (`javadoc-proxy#class-proxy`).

The snippet creates a JDK dynamic proxy of a `Greeter` interface whose handler records each call and forwards `greet` to a target.

```java snippet=m01-l02/ProxyDispatch.java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Modifier;
import java.lang.reflect.Proxy;
import java.util.ArrayList;
import java.util.List;

public class ProxyDispatch {
    interface Greeter {
        String greet(String name);
    }

    public static void main(String[] args) {
        Greeter target = name -> "hello " + name;
        List<String> calls = new ArrayList<>();
        InvocationHandler handler = (proxy, method, arguments) -> {
            calls.add(method.getDeclaringClass().getSimpleName() + "." + method.getName());
            if (method.getName().equals("toString")) {
                return "proxy";
            }
            return method.invoke(target, arguments);
        };
        Greeter greeter = (Greeter) Proxy.newProxyInstance(
                Greeter.class.getClassLoader(), new Class<?>[] {Greeter.class}, handler);
        System.out.println(greeter.greet("Ana"));
        System.out.println(greeter);
        System.out.println(calls);
        System.out.println(Proxy.isProxyClass(greeter.getClass()));
        System.out.println(Modifier.isFinal(greeter.getClass().getModifiers()));
        System.out.println(greeter.getClass().getSuperclass().getName());
    }
}
```

The snippet prints `hello Ana`, which the handler returned from the target, and `proxy`, which the handler returned for `toString`.

It prints `[Greeter.greet, Object.toString]`, so the handler saw the interface method and the `Object` method alike.

It prints `true` for `Proxy.isProxyClass`, `true` for the `final` modifier of the proxy class, and `java.lang.reflect.Proxy` as the name of its superclass.

:::diagram{kind="sequence" caption="A call on a JDK proxy reaches its invocation handler"}
description: The caller invokes greet on the proxy instance, the proxy dispatches the call to the invoke method of its invocation handler, and the handler forwards greet to the target, which returns hello Ana.

:::

Spring AOP uses either JDK dynamic proxies or CGLIB to create the proxy for a given target object (`spring-fw-aop-proxying#proxying-mechanisms`).

JDK dynamic proxies are built into the JDK, whereas CGLIB is a common open-source class definition library repackaged into `spring-core` (`spring-fw-aop-proxying#proxying-mechanisms`).

If the target object to be proxied implements at least one interface, a JDK dynamic proxy is used, and all of the interfaces implemented by the target type are proxied (`spring-fw-aop-proxying#proxying-mechanisms`).

If the target object does not implement any interfaces, a CGLIB proxy is created, which is a runtime-generated subclass of the target type (`spring-fw-aop-proxying#proxying-mechanisms`).

When CGLIB proxying is forced, `final` classes cannot be proxied, because they cannot be extended (`spring-fw-aop-proxying#proxying-mechanisms`).

When CGLIB proxying is forced, `final` methods and `private` methods cannot be advised, because they cannot be overridden (`spring-fw-aop-proxying#proxying-mechanisms`).

You can define an HTTP service as a Java interface with `@HttpExchange` methods, and use `HttpServiceProxyFactory` to create a client proxy from it for remote access over HTTP via `RestClient`, `WebClient` or `RestTemplate` (`spring-fw-integration-rest-clients#rest-http-service-client`).

`@Cacheable` marks methods whose result is stored in the cache, so that on subsequent invocations with the same arguments the value in the cache is returned without actually invoking the method (`spring-fw-cache-annotations#cache-annotations-cacheable`).

The default advice mode for processing caching annotations is proxy, which allows for interception of calls through the proxy only (`spring-fw-cache-annotations#cache-annotation-enable`).

In proxy mode, self-invocation does not lead to actual caching at runtime even if the invoked method is marked with `@Cacheable` (`spring-fw-cache-annotations#cache-annotation-enable`).

When you use proxies, you should apply the cache annotations only to methods with public visibility (`spring-fw-cache-annotations#cache-annotation-enable`).

```java snippet=m01-l02/CacheProxy.java
import org.springframework.aop.support.AopUtils;
import org.springframework.cache.CacheManager;
import org.springframework.cache.annotation.Cacheable;
import org.springframework.cache.annotation.EnableCaching;
import org.springframework.cache.concurrent.ConcurrentMapCacheManager;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

public class CacheProxy {
    static int loads;

    static class Prices {
        @Cacheable("prices")
        public int price(String sku) {
            loads++;
            return sku.length() * 100;
        }

        public int again(String sku) {
            return price(sku);
        }
    }

    @Configuration
    @EnableCaching
    static class Config {
        @Bean
        CacheManager cacheManager() {
            return new ConcurrentMapCacheManager("prices");
        }

        @Bean
        Prices prices() {
            return new Prices();
        }
    }

    public static void main(String[] args) {
        try (var context = new AnnotationConfigApplicationContext(Config.class)) {
            Prices prices = context.getBean(Prices.class);
            System.out.println(AopUtils.isCglibProxy(prices));
            prices.price("tea");
            prices.price("tea");
            System.out.println(loads);
            prices.again("tea");
            System.out.println(loads);
        }
    }
}
```

The bean prints `true` for `AopUtils.isCglibProxy`, because `Prices` implements no interface.

Two calls to `price("tea")` through the bean leave `loads` at `1`, since the second call came from the cache. A call to `again("tea")`, which calls `price` on `this`, raises it to `2`.

The most important concepts of the Spring Framework's declarative transaction support are that it is enabled via AOP proxies and that the transactional advice is driven by metadata (`spring-fw-tx-declarative-tx-decl-explained#page-title`).

## Comparator, Executor and Flow
<!-- bullets: 1.2.c -->

:::judgement{source="Gamma, Helm, Johnson and Vlissides, Design Patterns, 1st edition (1994)"}
According to the course's registered chapter list, Design Patterns covers behavioural patterns in chapter 5, "Behavioral Patterns".
:::

A `Comparator` is passed to a sort method to control the sort order. An `Executor` takes a `Runnable` and decides how it runs, which can be in the calling thread. A `Flow.Subscriber` receives the items that a publisher produces.

A `Comparator` is a comparison function, which imposes a total ordering on some collection of objects (`javadoc-comparator#interface-comparator-t`).

Comparators can be passed to a sort method, such as `Collections.sort` or `Arrays.sort`, to allow precise control over the sort order (`javadoc-comparator#interface-comparator-t`).

`Collections.sort(list, c)` sorts the list according to the order induced by the specified comparator (`javadoc-collections#sort(java.util.List,java.util.Comparator)`).

A null comparator indicates that the elements' natural ordering should be used (`javadoc-collections#sort(java.util.List,java.util.Comparator)`).

```java snippet=m01-l02/SortOrders.java
import java.util.ArrayList;
import java.util.Collections;
import java.util.Comparator;
import java.util.List;

public class SortOrders {
    public static void main(String[] args) {
        List<String> words = new ArrayList<>(List.of("pear", "fig", "apple"));
        Collections.sort(words, Comparator.comparingInt(String::length));
        System.out.println(words);
        Collections.sort(words, null);
        System.out.println(words);
        Collections.sort(words, Comparator.<String>naturalOrder().reversed());
        System.out.println(words);
    }
}
```

Sorting by `Comparator.comparingInt(String::length)` gives `[fig, pear, apple]`, and a `null` comparator gives the natural order `[apple, fig, pear]`. The reversed natural order gives `[pear, fig, apple]`.

An `Executor` is an object that executes submitted `Runnable` tasks (`javadoc-executor#interface-executor`).

The `Executor` interface provides a way of decoupling task submission from the mechanics of how each task will be run, including details of thread use and scheduling (`javadoc-executor#interface-executor`).

The `Executor` interface does not strictly require that execution be asynchronous (`javadoc-executor#interface-executor`).

The command given to `execute` may run in a new thread, in a pooled thread, or in the calling thread, at the discretion of the `Executor` implementation (`javadoc-executor#execute(java.lang.Runnable)`).

```java snippet=m01-l02/CommandExecutors.java
import java.util.concurrent.Executor;

public class CommandExecutors {
    public static void main(String[] args) throws InterruptedException {
        Runnable command = () -> System.out.println(Thread.currentThread().getName());
        Executor direct = Runnable::run;
        direct.execute(command);
        Executor threadPerTask = task -> {
            Thread worker = new Thread(task, "worker");
            worker.start();
            try {
                worker.join();
            } catch (InterruptedException e) {
                throw new IllegalStateException(e);
            }
        };
        threadPerTask.execute(command);
    }
}
```

One `Runnable` runs under two executors. The one that calls `run` directly prints `main`, and the one that starts a thread for each task prints `worker`.

`Flow` holds interrelated interfaces for flow-controlled components in which publishers produce items consumed by one or more subscribers, each managed by a subscription (`javadoc-flow#class-flow`).

A `Flow.Subscriber` arranges that items be requested and processed (`javadoc-flow#class-flow`).

Items are not issued to a `Flow.Subscriber` unless requested, but multiple items may be requested (`javadoc-flow#class-flow`).

The snippet gives a `Checkout` a discount function chosen by its caller and a list of listeners that are told the total.

```java snippet=m01-l02/StrategyObserver.java
import java.util.ArrayList;
import java.util.List;
import java.util.function.Consumer;
import java.util.function.LongUnaryOperator;

public class StrategyObserver {
    static final class Checkout {
        private final LongUnaryOperator discount;
        private final List<Consumer<Long>> listeners = new ArrayList<>();

        Checkout(LongUnaryOperator discount) {
            this.discount = discount;
        }

        void subscribe(Consumer<Long> listener) {
            listeners.add(listener);
        }

        long pay(long cents) {
            long total = discount.applyAsLong(cents);
            listeners.forEach(listener -> listener.accept(total));
            return total;
        }
    }

    public static void main(String[] args) {
        Checkout half = new Checkout(cents -> cents / 2);
        half.subscribe(total -> System.out.println("audit " + total));
        half.subscribe(total -> System.out.println("mail " + total));
        System.out.println(half.pay(1000));
        System.out.println(new Checkout(cents -> cents).pay(1000));
    }
}
```

The snippet prints `audit 500` and `mail 500` first, one per listener in subscription order, and then `500`, the value `pay` returned for the halving discount.

It prints `1000` for the checkout built with the identity discount, which has no listeners.

## AbstractList and FilterChain
<!-- bullets: 1.2.c -->

`AbstractList` is a skeletal implementation of `List`: a subclass supplies `get` and `size` for an unmodifiable list and the class supplies the iterator, while `add` fails until the subclass overrides `add(int, E)`. A servlet filter chain passes a request through filters in order, and each filter decides whether the rest of the chain runs.

`AbstractList` provides a skeletal implementation of the `List` interface to minimize the effort required to implement this interface backed by a "random access" data store (`javadoc-abstractlist#class-abstractlist-e`).

To implement an unmodifiable list, the programmer needs only to extend this class and provide implementations for the `get(int)` and `size()` methods (`javadoc-abstractlist#class-abstractlist-e`).

The programmer does not have to provide an iterator implementation, because the iterator and list iterator are implemented by this class on top of the "random access" methods `get(int)`, `set(int, E)`, `add(int, E)` and `remove(int)` (`javadoc-abstractlist#class-abstractlist-e`).

The documentation for each non-abstract method in this class describes its implementation in detail, and each of these methods may be overridden if the collection being implemented admits a more efficient implementation (`javadoc-abstractlist#class-abstractlist-e`).

`AbstractList.add(E)` calls `add(size(), e)` and throws `UnsupportedOperationException` unless `add(int, E)` is overridden (`javadoc-abstractlist#add(java.lang.Object)`).

```java snippet=m01-l02/SkeletalList.java
import java.util.AbstractList;
import java.util.List;

public class SkeletalList {
    static final class Squares extends AbstractList<Integer> {
        private final int size;

        Squares(int size) {
            this.size = size;
        }

        @Override
        public Integer get(int index) {
            return index * index;
        }

        @Override
        public int size() {
            return size;
        }
    }

    public static void main(String[] args) {
        List<Integer> squares = new Squares(5);
        StringBuilder seen = new StringBuilder();
        for (int square : squares) {
            seen.append(square).append(' ');
        }
        System.out.println(seen.toString().trim());
        try {
            squares.add(25);
        } catch (UnsupportedOperationException e) {
            System.out.println("add is not implemented");
        }
    }
}
```

The `for` loop prints `0 1 4 9 16` through the iterator that `AbstractList` supplied over `get` and `size`. A call to `add` prints `add is not implemented`, because `Squares` does not override `add(int, E)`.

The container creates a `FilterChain`, which contains the `Filter` instances and the `Servlet` that should process the `HttpServletRequest`, based on the path of the request URI (`spring-security-servlet-architecture#servlet-filters-review`).

More than one `Filter` can be used to prevent downstream `Filter` instances or the `Servlet` from being invoked, or to modify the request or response used by the downstream `Filter` instances and the `Servlet` (`spring-security-servlet-architecture#servlet-filters-review`).

In the `FilterChain` usage example, a `Filter` does something before the rest of the application, calls `chain.doFilter` to invoke the rest of the application, and then does something after it (`spring-security-servlet-architecture#servlet-filters-review`).

Since a `Filter` impacts only downstream `Filter` instances and the `Servlet`, the order in which each `Filter` is invoked is extremely important (`spring-security-servlet-architecture#servlet-filters-review`).

`FilterChainProxy` decides which `SecurityFilterChain` should be used, and only the first `SecurityFilterChain` that matches is invoked (`spring-security-servlet-architecture#servlet-securityfilterchain`).

## Key points

- `Executors.newFixedThreadPool(int)` throws `IllegalArgumentException` when `nThreads <= 0` (`javadoc-executors#newFixedThreadPool(int)`).
- `HttpClient.newHttpClient()` is equivalent to `newBuilder().build()`, and `HttpRequest.newBuilder(URI)` throws `IllegalArgumentException` for an unsupported URI scheme (`javadoc-java-net-http-httpclient#newHttpClient()`; `javadoc-java-net-http-httprequest#newBuilder(java.net.URI)`).
- The snippet's builder throws an `IllegalStateException` from `build` when `cents` was never set, so no `Invoice` is constructed.
- `Collections.synchronizedList` returns a thread-safe list backed by the specified list, and all access must go through the returned list (`javadoc-collections#synchronizedList(java.util.List)`).
- `RestClient` adapts HTTP libraries through the `ClientRequestFactory` interface (`spring-fw-integration-rest-clients#rest-request-factories`).
- A JDK proxy class is created at runtime, implements the proxy interfaces, is final and extends `java.lang.reflect.Proxy` (`javadoc-proxy#class-proxy`).
- A call on a proxy instance reaches the `invoke` method of its invocation handler, and so do `hashCode`, `equals` and `toString` (`javadoc-proxy#class-proxy`).
- Spring AOP uses a JDK dynamic proxy when the target implements at least one interface, and a CGLIB runtime-generated subclass when it implements none (`spring-fw-aop-proxying#proxying-mechanisms`).
- With CGLIB proxying, `final` classes cannot be proxied and `final` and `private` methods cannot be advised (`spring-fw-aop-proxying#proxying-mechanisms`).
- In proxy mode, self-invocation does not lead to actual caching even if the invoked method is marked with `@Cacheable` (`spring-fw-cache-annotations#cache-annotation-enable`).
- The command given to `Executor.execute` may run in a new thread, in a pooled thread, or in the calling thread (`javadoc-executor#execute(java.lang.Runnable)`).
- A subclass of `AbstractList` needs only `get(int)` and `size()` to implement an unmodifiable list (`javadoc-abstractlist#class-abstractlist-e`).
- A `Filter` can prevent downstream `Filter` instances or the `Servlet` from being invoked, and only the first matching `SecurityFilterChain` is invoked (`spring-security-servlet-architecture#servlet-filters-review`; `spring-security-servlet-architecture#servlet-securityfilterchain`).
