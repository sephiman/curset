Conceptos de minería de datos

En este artículo

Se aplica a: SQL Server 2019 y versiones anteriores de Analysis Services Azure Analysis Services Fabric/Power BI Premium

Importante

La minería de datos estaba en desuso en SQL Server 2017 Analysis Services y ahora se descontinuó en SQL Server 2022 Analysis Services. La documentación no se actualiza para las características en desuso y descontinuadas. Para más información, consulte Compatibilidad con versiones anteriores de Analysis Services.

La minería de datos es el proceso de detectar información accionable de grandes conjuntos de datos. La minería de datos usa análisis matemáticos para derivar patrones y tendencias que existen en los datos. Normalmente, estos patrones no se pueden detectar mediante la exploración de datos tradicional porque las relaciones son demasiado complejas o porque hay demasiados datos.

Estos patrones y tendencias se pueden recopilar y definir como modelo de minería de datos. Los modelos de minería de datos se pueden aplicar a escenarios específicos, como:

  • Previsión: Estimación de ventas, predicción de cargas de servidor o tiempo de inactividad del servidor

  • Riesgo y probabilidad: elegir a los mejores clientes para correos dirigidos, determinar el punto de equilibrio probable para escenarios de riesgo, asignar probabilidades a diagnósticos u otros resultados

  • Recomendaciones: determinar qué productos probablemente se venden juntos, generando recomendaciones

  • Buscar secuencias: Análisis de selecciones de clientes en un carro de la compra, predicción de los próximos eventos probables

  • Agrupación: separación de clientes o eventos en un clúster de elementos relacionados, análisis y predicción de afinidades

La creación de un modelo de minería de datos forma parte de un proceso mayor que incluye todo, desde hacer preguntas sobre los datos y crear un modelo para responder a esas preguntas, para implementar el modelo en un entorno de trabajo. Este proceso se puede definir mediante los seis pasos básicos siguientes:

  1. Definición del problema

  2. Preparación de datos

  3. Exploración de datos

  4. Compilar modelos

  5. Exploración y validación de modelos

  6. Implementación y actualización de modelos

En el diagrama siguiente se describen las relaciones entre cada paso del proceso y las tecnologías de Microsoft SQL Server que puede usar para completar cada paso.

El proceso que se muestra en el diagrama es cíclico, lo que significa que la creación de un modelo de minería de datos es un proceso dinámico e iterativo. Después de explorar los datos, puede que estos no sean suficientes para crear los modelos de minería adecuados y, por lo tanto, tenga que buscar más información. Como alternativa, puede crear varios modelos y, a continuación, darse cuenta de que los modelos no responden adecuadamente al problema definido y, por tanto, debe redefinir el problema. Es posible que tenga que actualizar los modelos una vez implementados porque hay más datos disponibles. Es posible que cada paso del proceso tenga que repetirse muchas veces para crear un buen modelo.

La minería de datos de Microsoft SQL Server proporciona un entorno integrado para crear y trabajar con modelos de minería de datos. Este entorno incluye SQL Server Development Studio, que contiene algoritmos de minería de datos y herramientas de consulta que facilitan la compilación de una solución completa para una variedad de proyectos y SQL Server Management Studio, que contiene herramientas para examinar modelos y administrar objetos de minería de datos. Para obtener más información, vea Creación de modelos multidimensionales mediante SQL Server Data Tools (SSDT).

Para obtener un ejemplo de cómo se pueden aplicar las herramientas de SQL Server a un escenario empresarial, consulte el Tutorial básico de minería de datos.

Definición del problema

El primer paso del proceso de minería de datos, como se resalta en el diagrama siguiente, consiste en definir claramente el problema y considerar las formas en que se pueden usar los datos para proporcionar una respuesta al problema.

Este paso incluye el análisis de los requisitos empresariales, la definición del ámbito del problema, la definición de las métricas por las que se evaluará el modelo y la definición de objetivos específicos para el proyecto de minería de datos. Estas tareas se traducen en preguntas como las siguientes:

  • ¿Qué buscas? ¿Qué tipos de relaciones intenta encontrar?

  • ¿El problema que intenta resolver refleja las directivas o los procesos de la empresa?

  • ¿Desea realizar predicciones desde el modelo de minería de datos o simplemente buscar patrones y asociaciones interesantes?

  • ¿Qué resultado o atributo desea intentar predecir?

  • ¿Qué tipo de datos tiene y qué tipo de información hay en cada columna? Si hay varias tablas, ¿cómo están relacionadas las tablas? ¿Necesita realizar cualquier limpieza, agregación o procesamiento para que los datos se puedan usar?

  • ¿Cómo se distribuyen los datos? ¿Los datos son estacionales? ¿Los datos representan con precisión los procesos de la empresa?

Para responder a estas preguntas, es posible que tenga que realizar un estudio de disponibilidad de datos para investigar las necesidades de los usuarios empresariales con respecto a los datos disponibles. Si los datos no admiten las necesidades de los usuarios, es posible que tenga que volver a definir el proyecto.

También debe tener en cuenta las formas en que los resultados del modelo se pueden incorporar en los indicadores clave de rendimiento (KPI) que se usan para medir el progreso empresarial.

Preparación de datos

El segundo paso del proceso de minería de datos, como se resalta en el diagrama siguiente, consiste en consolidar y limpiar los datos identificados en el paso Definir el problema .

Los datos se pueden dispersar en una empresa y almacenarse en diferentes formatos, o pueden contener incoherencias, como entradas incorrectas o que faltan. Por ejemplo, los datos podrían mostrar que un cliente compró un producto antes de que el producto se ofreciera en el mercado, o que los clientes tiendan regularmente en una tienda ubicada a 2.000 millas de su casa.

La limpieza de datos no se trata solo de quitar datos incorrectos o interpolar valores que faltan, sino de buscar correlaciones ocultas en los datos, identificar orígenes de datos que son los más precisos y determinar qué columnas son las más adecuadas para su uso en el análisis. Por ejemplo, ¿debe usar la fecha de envío o la fecha de pedido? ¿Es el mejor influenciador de ventas la cantidad, el precio total o un precio con descuento? Los datos incompletos, los datos incorrectos y las entradas que aparecen independientes, pero de hecho están estrechamente correlacionados, todos pueden influir en los resultados del modelo de maneras que no se esperan.

Por lo tanto, antes de empezar a crear modelos de minería de datos, debe identificar estos problemas y determinar cómo se corregirán. En el caso de la minería de datos, normalmente está trabajando con un conjunto de datos muy grande y no puede examinar todas las transacciones de calidad de los datos; Por lo tanto, es posible que tenga que usar algún tipo de generación de perfiles de datos y herramientas automatizadas de limpieza y filtrado de datos, como las proporcionadas en Integration Services, Microsoft SQL Server 2012 Master Data Services o SQL Server Data Quality Services para explorar los datos y buscar las incoherencias. Para obtener más información, vea estos recursos:

  • Integration Services en Business Intelligence Development Studio

  • Introducción a Master Data Services (MDS)

  • Data Quality Services

Es importante tener en cuenta que los datos que se usan para la minería de datos no necesitan almacenarse en un cubo de procesamiento analítico en línea (OLAP) o incluso en una base de datos relacional, aunque puede usar ambos como orígenes de datos. Puede realizar la minería de datos mediante cualquier origen de datos que se haya definido como origen de datos de SQL Server Analysis Services. Pueden incluir archivos de texto, libros de Excel o datos de otros proveedores externos. Para obtener más información, vea Orígenes de datos admitidos (SSAS - Multidimensional) .

Exploración de datos

El tercer paso del proceso de minería de datos, como se resalta en el diagrama siguiente, es explorar los datos preparados.

Debe comprender los datos para tomar decisiones adecuadas al crear modelos de minería de datos. Las técnicas de exploración incluyen calcular los valores mínimo y máximo, calcular las desviaciones medias y estándar y examinar la distribución de los datos. Por ejemplo, puede determinar revisando los valores máximos, mínimos y medios que los datos no son representativos de los clientes o los procesos empresariales y, por tanto, debe obtener datos más equilibrados o revisar las suposiciones que son la base de sus expectativas. Las desviaciones estándar y otros valores de distribución pueden proporcionar información útil sobre la estabilidad y la precisión de los resultados. Una desviación estándar grande puede indicar que agregar más datos puede ayudarle a mejorar el modelo. Los datos que se desvieron fuertemente de una distribución estándar podrían estar sesgados o podrían representar una imagen precisa de un problema real, pero dificultar la adaptación de un modelo a los datos.

Al explorar los datos a la luz de su propia comprensión del problema empresarial, puede decidir si el conjunto de datos contiene datos defectuosos y, a continuación, puede diseñar una estrategia para corregir los problemas o obtener una comprensión más profunda de los comportamientos que son típicos de su negocio.

Puede usar herramientas como Master Data Services para examinar orígenes de datos disponibles y determinar su disponibilidad para la minería de datos. Puede usar herramientas como SQL Server Data Quality Services o Data Profiler en Integration Services para analizar la distribución de los datos y reparar problemas, como datos incorrectos o que faltan.

Después de definir los orígenes, puede combinarlos en una vista del origen de datos mediante el Diseñador de vistas del origen de datos en SQL Server Data Tools. Para obtener más información, vea Vistas del origen de datos en modelos multidimensionales. Este diseñador también contiene algunas herramientas que puede usar para explorar los datos y comprobar que funcionará para crear un modelo. Para obtener más información, vea Explorar datos en una vista de origen de datos (Analysis Services).

Tenga en cuenta que, al crear un modelo, SQL Server Analysis Services crea automáticamente resúmenes estadísticos de los datos contenidos en el modelo, que puede consultar para usarlos en informes o análisis adicionales. Para obtener más información, consulte Consultas de minería de datos.

Compilar modelos

El cuarto paso del proceso de minería de datos, como se resalta en el diagrama siguiente, es crear el modelo de minería de datos o los modelos. Usará el conocimiento que obtuvo en el paso Explorar datos para ayudar a definir y crear los modelos.

Para definir las columnas de datos que desea utilizar, cree una estructura de minería. La estructura de minería de datos está vinculada al origen de datos, pero realmente no contiene ningún dato hasta que lo procese. Al procesar la estructura de minería de datos, SQL Server Analysis Services genera agregados y otra información estadística que se puede usar para el análisis. Cualquier modelo de minería de datos que se base en la estructura puede usar esta información. Para obtener más información sobre cómo están relacionadas las estructuras de minería de datos con los modelos de minería de datos, consulte Arquitectura lógica (Analysis Services - Minería de datos).

Antes de procesar la estructura y el modelo, un modelo de minería de datos también es un contenedor que especifica las columnas usadas para la entrada, el atributo que va a predecir y los parámetros que indican al algoritmo cómo procesar los datos. El procesamiento de un modelo se denomina a menudo entrenamiento. El entrenamiento hace referencia al proceso de aplicar un algoritmo matemático específico a los datos de la estructura para extraer patrones. Los patrones que se encuentran en el proceso de entrenamiento dependen de la selección de datos de entrenamiento, el algoritmo que eligió y cómo ha configurado el algoritmo. SQL Server 2017 contiene muchos algoritmos diferentes, cada uno adecuado para un tipo de tarea diferente y cada uno de ellos crea un tipo de modelo diferente. Para obtener una lista de los algoritmos proporcionados en SQL Server 2017, vea Algoritmos de minería de datos (Analysis Services - Minería de datos).

También puede usar parámetros para ajustar cada algoritmo y puede aplicar filtros a los datos de entrenamiento para usar solo un subconjunto de los datos, creando resultados diferentes. Después de pasar datos a través del modelo, el objeto del modelo de minería contiene resúmenes y patrones que se pueden consultar o usar para la predicción.

Puede definir un nuevo modelo mediante el Asistente para minería de datos en SQL Server Data Tools o mediante el lenguaje Extensiones de minería de datos (DMX). Para obtener más información sobre cómo usar el Asistente para minería de datos, consulte Asistente para minería de datos (Analysis Services - Minería de datos). Para obtener más información sobre cómo usar DMX, vea Referencia de extensiones de minería de datos (DMX).

Es importante recordar que cada vez que cambian los datos, debe actualizar tanto la estructura de minería como el modelo de minería. Al actualizar una estructura de minería de datos mediante su reprocesamiento, SQL Server Analysis Services recupera datos del origen, incluidos los nuevos datos si el origen se actualiza dinámicamente y vuelve a rellenar la estructura de minería de datos. Si tiene modelos basados en la estructura, puede elegir actualizar los modelos que se basan en la estructura, lo que significa que se vuelven a entrenar en los nuevos datos o puede dejar los modelos tal cual. Para obtener más información, vea Requisitos y consideraciones de procesamiento (minería de datos).

Exploración y validación de modelos

El quinto paso del proceso de minería de datos, como se resalta en el diagrama siguiente, es explorar los modelos de minería de datos que ha creado y probar su eficacia.

Antes de implementar un modelo en un entorno de producción, querrá probar el rendimiento del modelo. Además, al compilar un modelo, normalmente se crean varios modelos con distintas configuraciones y se prueban todos los modelos para ver cuáles generan los mejores resultados para el problema y los datos.

SQL Server Analysis Services proporciona herramientas que le ayudan a separar los datos en conjuntos de datos de entrenamiento y pruebas para que pueda evaluar con precisión el rendimiento de todos los modelos en los mismos datos. Use el conjunto de datos de entrenamiento para compilar el modelo y el conjunto de datos de prueba para probar la precisión del modelo mediante la creación de consultas de predicción. Esta creación de particiones se puede realizar automáticamente al compilar el modelo de minería de datos. Para obtener más información, vea Testing and Validation (Data Mining).

Puede explorar las tendencias y patrones que detectan los algoritmos mediante los visores del Diseñador de minería de datos en SQL Server Data Tools. Para obtener más información, consulte Visores de modelos de minería de datos. También puede probar la forma en que los modelos crean predicciones mediante herramientas en el diseñador, como el gráfico de elevación y la matriz de clasificación. Para comprobar si el modelo es específico de los datos o puede usarse para realizar inferencias en la población general, puede usar la técnica estadística denominada validación cruzada para crear automáticamente subconjuntos de los datos y probar el modelo contra cada subconjunto. Para obtener más información, vea Testing and Validation (Data Mining).

Si ninguno de los modelos que creó en el paso Construcción de Modelos funciona bien, es posible que tenga que regresar a un paso anterior del proceso y redefinir el problema o reinvestigar los datos del conjunto de datos original.

Implementación y actualización de modelos

El último paso del proceso de minería de datos, como se resalta en el diagrama siguiente, es implementar los modelos que han realizado lo mejor para un entorno de producción.

Después de que los modelos de minería de datos existan en un entorno de producción, puede realizar muchas tareas, en función de sus necesidades. A continuación se muestran algunas de las tareas que puede realizar:

  • Use los modelos para crear predicciones, que puede usar para tomar decisiones empresariales. SQL Server proporciona el lenguaje DMX que puede usar para crear consultas de predicción y generador de consultas de predicción para ayudarle a crear las consultas. Para más información, vea Referencia de Extensiones de minería de datos (DMX).

  • Cree consultas de contenido para recuperar estadísticas, reglas o fórmulas del modelo. Para obtener más información, consulte Consultas de minería de datos.

  • Inserte la funcionalidad de minería de datos directamente en una aplicación. Puede incluir Objetos de Administración de Análisis (AMO), que contiene un conjunto de objetos que su aplicación puede usar para crear, modificar, procesar y eliminar estructuras y modelos de minería de datos. Como alternativa, puede enviar mensajes XML for Analysis (XMLA) directamente a una instancia de SQL Server Analysis Services. Para obtener más información, vea Desarrollo (Analysis Services - Minería de datos).

  • Use Integration Services para crear un paquete en el que se usa un modelo de minería de datos para separar de forma inteligente los datos entrantes en varias tablas. Por ejemplo, si una base de datos se actualiza continuamente con clientes potenciales, podría usar un modelo de minería de datos junto con Integration Services para dividir los datos entrantes en clientes que probablemente compren un producto y clientes que probablemente no compren un producto. Para obtener más información, consulte Usos típicos de Integration Services.

  • Cree un informe que permita a los usuarios consultar directamente un modelo de minería existente. Para obtener más información, vea Reporting Services en SQL Server Data Tools (SSDT).

  • Actualice los modelos después de la revisión y el análisis. Cualquier actualización requiere que se vuelvan a procesar los modelos. Para obtener más información, vea Procesamiento de objetos de minería de datos.

  • Actualice los modelos dinámicamente, a medida que haya más datos en la organización y realice cambios constantes para mejorar la eficacia de la solución debe formar parte de la estrategia de implementación. Para obtener más información, vea Administración de soluciones y objetos de minería de datos.
