# Pattern recognition

## Signals for backtracking
<!-- bullets: 2.7.a -->

:::judgement{source="Jeff Erickson, Algorithms, chapter on backtracking" ref="erickson-backtracking#p9"}
According to Jeff Erickson, a problem whose goal is a sequence of decisions, such as where to place the queen in each row or whether to include each input element, is a candidate for backtracking. In his formulation each recursive call makes exactly one decision that is consistent with the earlier ones, so the data structure to choose is a summary of the decisions already made, and it should be as small as possible.
:::

## Signals for dynamic programming
<!-- bullets: 2.7.a -->

:::judgement{source="Jeff Erickson, Algorithms, chapter on dynamic programming" ref="erickson-dynamic-programming#p9"}
According to Jeff Erickson, dynamic programming is recursion without repetition. His text segmentation example shows the signal: the backtracking algorithm takes exponential time, yet for a fixed string there are only n different ways to call the recursive function, so the same subproblems repeat.
:::

:::judgement{source="Jeff Erickson, Algorithms, chapter on dynamic programming" ref="erickson-dynamic-programming#p11"}
According to Jeff Erickson, once the subproblems are identified the remaining steps are to choose a memoization data structure, identify the dependencies between subproblems, find an evaluation order, analyse the space and running time, and write down the algorithm. He says the number of distinct subproblems gives the space complexity of the memoized algorithm.
:::

## Signals for a greedy algorithm
<!-- bullets: 2.7.a -->

:::judgement{source="Jeff Erickson, Algorithms, chapter on dynamic programming" ref="erickson-dynamic-programming#p11"}
According to Jeff Erickson, a greedy strategy is many students' first intuition for problems that should be solved by backtracking or dynamic programming, and it almost never works.
:::

:::judgement{source="Jeff Erickson, Algorithms, chapter on greedy algorithms" ref="erickson-greedy#p3"}
According to Jeff Erickson, when file sizes and access frequencies both vary, the files should be sorted by the ratio of length to frequency, and swapping two adjacent files that are out of order improves the total cost.
:::

## The cost of the naive and the better solution
<!-- bullets: 2.7.a -->

:::esquema{kind=tabla title="Naive and better solutions in Erickson's examples"}
| Problem | Solution | What the book states | Citation |
| --- | --- | --- | --- |
| Text segmentation | Recursive backtracking | Calls `IsWord` `O(2^n)` times in the worst case | `erickson-dynamic-programming#p9` |
| Text segmentation | Dynamic programming | Makes `O(n^2)` calls to `IsWord`, an exponential improvement | `erickson-dynamic-programming#p9` |
| Longest increasing subsequence | Recursive backtracking | Both backtracking algorithms run in `O(2^n)` time in the worst case | `erickson-dynamic-programming#p13` |
| Longest increasing subsequence | Dynamic programming | The array-based algorithm runs in `O(n^2)` time and uses `O(n)` space | `erickson-dynamic-programming#p15` |
:::

## Key points

- A backtracking algorithm and a dynamic programming algorithm for text segmentation call `IsWord` `O(2^n)` and `O(n^2)` times in the worst case.
- The two backtracking algorithms for the longest increasing subsequence run in `O(2^n)` time, and the array-based dynamic programming algorithm runs in `O(n^2)` time and uses `O(n)` space.
